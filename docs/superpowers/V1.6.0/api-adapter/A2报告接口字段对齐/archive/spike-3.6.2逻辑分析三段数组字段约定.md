# A2 · 3.6.2 问题链逻辑分析字段类型约定（后端调整）

**日期：** 2026-09-08  
**路径前缀：** `aReport.newKnowledgeTeaching.teacherQuestioning.questionChainAnalysis.logicAnalysis`

以下三项原页面 mock 为**多条文案列表**；请改为 **`string[]`**，不要再返回单个 `string`。  
前端按数组顺序逐条渲染；`null` / `[]` 视为该小节暂无内容。

---

## 字段一览

| 页面小节 | 字段名 | 类型 | 说明 |
|----------|--------|------|------|
| （二）逻辑线索分析 | `logicalClue` | `string[]` | 多条独立文案 |
| （三）目标指向分析 | `goalOrientation` | `string[]` | 多条独立文案 |
| （四）完整性与闭环分析 | `closureAnalysis` | `string[]` | 多条独立文案 |

**不要：** `"logicalClue": "一整段……"`  
**要：** `"logicalClue": ["第一条", "第二条", …]`

---

## 推荐条数与文案形态（对齐原 mock）

### `logicalClue`（二）

建议 3 条（条数可增减，按实际内容）：

1. `逻辑关系类型：……`
2. `衔接方式：……`
3. `线索清晰度：……`

```json
"logicalClue": [
  "逻辑关系类型：递进+归纳",
  "衔接方式：教师在每个问题之间都给予了及时的引导和反馈，帮助学生确认当前进展后再进入下一步。",
  "线索清晰度：清晰。"
]
```

### `goalOrientation`（三）

建议 3 条：

1. `目标指向：……`
2. `与重难点的关联：……`
3. `目标达成效果：……`

```json
"goalOrientation": [
  "目标指向：解决池塘测距问题，直接对应重难点1和2。",
  "与重难点的关联：紧密——这是本节课的核心例题。",
  "目标达成效果：有效。"
]
```

### `closureAnalysis`（四）

建议 4 条：

1. `起点问题：……`
2. `推进过程：……`
3. `收束方式：……`
4. `闭环判断：……`

```json
"closureAnalysis": [
  "起点问题：用什么方式测量（方向选择）",
  "推进过程：拉绳子 → 能否用全等 → 还缺什么（方法判断 → 识别不足）",
  "收束方式：延长构造全等，得出结论AB=EF",
  "闭环判断：完整。"
]
```

## 后端自查

- [ ] `logicalClue` / `goalOrientation` / `closureAnalysis` 均为 `string[]`（或 `null`）
- [ ] 每条是完整一句展示文案，不要把多条拼成一个长 string 再塞进数组唯一元素（除非业务确实只有一条）
- [ ] 无内容时返回 `[]` 或 `null`，不要返回 `""`
