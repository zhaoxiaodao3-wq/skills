# 课堂教学内容报告：reportType / reportSubType 修改概要

> 模块：`docs/superpowers/V1.6.0/api-adapter/课堂教学内容报告子类型`  
> 日期：2026-08-25  
> 页面：`classroom-content-analysis`（课堂教学内容分析）

---

## 1. 改了什么

### 之前（第二版）

`reportType` 同时承担「大类」和「子版本」：

- `A` / `A1` / `A2` / `B` / `B1` / `B2` 都塞在同一个字段里。

### 现在

| 字段 | 合法值 | 谁提供 | 作用 |
|------|--------|--------|------|
| **`reportType`** | **仅 `A` / `B` / `G`** | 后端已有 | 大类：AB 走内容分析菜单；G 走 G 菜单 |
| **`reportSubType`** | `A1` / `A2` / `B1` / `B2` | **后端暂未下发**（前端可选 / mock） | 子版本：决定用哪套 mapper / registry |

### 缺省规则（保证不影响现网）

| `reportType` | `reportSubType` | 实际子版本 | 页面表现 |
|--------------|-----------------|------------|----------|
| `A` | 空 / 未传 | **A1** | 现有 A 类报告页 |
| `B` | 空 / 未传 | **B1** | 现有 B 类报告页 |
| `A` | `A2` | A2 | A2 mapper（结构变化时独立实现） |
| `B` | `B2` | B2 | B2 mapper |

解析入口：

```ts
parseReportVariant(reportType, reportSubType?)
getClassroomContentReportConfigByType(reportType, reportSubType?)
```

## 3. 字段怎么用（对接 / mock）

### 正式接口（后端日后补字段）

```json
{
  "caseBasicInfo": {
    "reportType": "A",
    "reportSubType": "A2"
  }
}
```

- snake_case `report_sub_type` 会经现有 `camelize` 变成 `reportSubType`。
- 暂时不传 `reportSubType`：**完全兼容现网**（A→A1，B→B1）。

### 本地 mock 验 A2 / B2

在 mock 的 `caseBasicInfo` 上临时加一行即可：

```ts
reportType: 'A',
reportSubType: 'A2', // 可选；不写则走 A1
```

## 4. 如何新增子类型（例如 A3 / B3）

按下面顺序改，**不要**把子版本写回 `reportType`。

### Step 1 — 白名单与元数据

文件：`utils/report-variant.ts`

1. 在 `REPORT_SUB_TYPES` 追加 `'A3'`（或 `'B3'`）
2. 在 `VARIANT_META` 增加对应项，例如：

```ts
A3: { variant: 'A3', family: 'A', version: 3, raw: 'A' },
```

3. **不要**改 `DIAGNOSIS_REPORT_TYPES`（大类仍只有 A/B/G）
4. 缺省映射 `DEFAULT_BY_FAMILY` 一般仍指向 A1/B1，除非产品要求改默认

### Step 2 — 独立 mapper（推荐）

新建（以 A3 为例）：

```text
src/pages/analysis-web/ai-teaching-diagnosis/mappers/classroom-content-analysis-a3.mapper.ts
```

- Phase 0 可先委托 `a.mapper`（参考现有 `a2.mapper.ts` / `b2.mapper.ts`）
- 结构与 A1 不同时，在该文件独立实现 `mapA3…` / `hasA3…`

### Step 3 — Registry 注册

文件：`classroom-diagnosis/registry/classroom-content-report-registry.ts`

1. import A3 mapper
2. 在 `REGISTRY` 增加一块（复制 A2 改名即可）：

```ts
A3: {
  variant: 'A3',
  view: ReportTypeAView, // 若 UI 大改再换新 View
  resolveReportData: (info) => info?.aReport,
  mapPayload: (…, rawReportType) => mapA3ReportToClassroomContentPayload(…, rawReportType),
  hasReportData: hasA3ReportData,
  resolvePageStatus: resolvePageStatusA,
  share: { ...FAMILY_SHARE.A },
},
```

### Step 4 — 单测

在 `report-variant.spec.ts` 补：

- `parseReportVariant('A', 'A3')` → `variant: 'A3'`
- 大类冲突用例（如 `reportType=B` + `reportSubType=A3` 应回落 B1）

### Step 5 — 本地验证

mock：`reportType: 'A', reportSubType: 'A3'`，打开内容分析页，确认走 A3 mapper。

## 5. 如何新增大类（极少见，例如将来有 C）

若产品真要第三大类（不只是 A/B 子版本），需要额外：

1. `DIAGNOSIS_REPORT_TYPES` / `CLASSROOM_CONTENT_REPORT_TYPES` 增加 `'C'`
2. `ReportFamily`、`DEFAULT_BY_FAMILY`、菜单分类、`FAMILY_SHARE`、新 View / 数据字段
3. 再按 §4 挂 C1/C2…

**日常迭代优先只加子类型（A3/B3），不要动大类。**
