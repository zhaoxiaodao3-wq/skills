# 分享报告架构 Registry · 原始需求

**工程：** `E:\code\H5\`（实现外链；本文档落在 frontend Harness）  
**档位：** 全量  
**P1 确认：** 2026-08-31 — 目标架构：Registry + Template + Shell + Family OG

## 1. 背景

H5 课后报告分享已有 A1 / B1 / B2 等多条路径，当前按「每类型一套目录 + 手写路由 + 碰 Vite/Nginx/OG」扩展。后续还要加 A2/A3/A4 等。

**本需求只解决架构结构**，不约束各报告（A1/B1/B2…）的章节内容、文案、业务字段。

## 2. 目标

落地可扩展结构：

| 层 | 职责 |
|----|------|
| **Variant** | 对外 URL / route name / family / OG·分享元数据 |
| **Template** | 渲染引擎（data → view → UI）；同结构复用，全新结构才新建 |
| **Shell** | 共用：`?code=` 拉数、过期态、loading、微信 JSSDK |
| **Registry** | 上述配置的单一事实来源；路由由 registry 生成 |
| **Family OG** | 按大类（A/B…）维护 HTML + Nginx；variant 差异在壳内按 path 分支 |

## 3. 非目标

- 不改写各报告业务章节内容与样式还原
- 不强制本迭代把 B2 等业务页重写成某种区块模型（可先「挂 shell + registry」，模板边界保留现状）
- 不改教师画像分享（`teacher-profile`）业务逻辑（可对齐同一 registry/OG 模式，但非必做）

## 4. 约束

- URL 规范：`/analysis-teaching-{family}{subtype}`（如 `a1`、`b2`）
- API 仍为统一 `getShareReport(token)`，类型由落地路径/registry 决定
- 开发与生产对分享 HTML 入口行为一致（dev middleware 覆盖 registry 全量 path）
- Nginx 按 **family 前缀**；新增独立 HTML 仅当新 family 或 OG 模板完全不同

## 5. 验收意向（架构）

- 新增一个 **同 template** 的 variant：原则上只改 registry（+ 必要时分享图常量），不必复制整目录
- 新增一个 **新 template**：只新增模板目录 + registry 一行，不复制 Shell
- Vite / Nginx / OG 与 registry 同源，无第三处硬编码 path 列表（允许构建时注入）

## 6. 交付物补充（P2 确认）

- 交付结束须出具一份**使用说明**（落在 H5 仓），方便同事按当前架构新增 Variant / Template / Family
- 旧链 `/analysis-teaching-a`、`/analysis-teaching-b`（无编号）：**redirect → a1 / b1**（默认策略，plan 可微调）
