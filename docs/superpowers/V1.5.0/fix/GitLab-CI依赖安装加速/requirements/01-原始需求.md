# GitLab CI 依赖安装加速 · 原始需求

**日期：** 2026-07-30  
**分类：** fix  
**版本：** V1.5.0（文档实体：frontend-local / skills.git）  
**提出方式：** `/harness`

## 需求原文

GitLab CI 构建非常慢，十几分钟花在 `pnpm install` 上。日志可见：

- Shell executor，每次 `Initialized empty Git repository` 全新 checkout
- `Restoring cache` 失败：`Cache file does not exist` / `No URL provided`
- `pnpm install` 约 12 分 29 秒；`Packages: +1078`，大量从 `nexus.mirayai.com` 下载
- 多次 `ECONNRESET` 后重试（10 秒 / 1 分钟），拖长时间
- 询问 `.gitlab-ci.yml` 是否有用、有何优化方式

## 现状（调研）

- `.gitlab-ci.yml` **有用且正在生效**：`build` job 执行 `pnpm install` + `pnpm build`
- 已配置 `cache.paths: [node_modules/]`，但对 pnpm **不足**（缺 store、无基于 lockfile 的 key），且 runner 上尚无可用缓存文件
- 慢的主因：**缓存未命中 + Nexus 下载慢/断连重试**，而非 Vite build 本身

## 成功标准（待方案确认）

- 缓存命中时 `pnpm install` 明显缩短（目标：从十几分钟降到约 1～3 分钟量级，视 runner 而定）
- lockfile 未变时尽量 `--prefer-offline` / 复用 store
- 不破坏现有 master/develop/test/csms 流水线与产物
