# 原始需求：教师画像详情页性能优化

**日期：** 2026-08-06
**分类：** fix
**实现仓：** `apps-development-platform/apps/data-cockpit`
**预览页：** `/data-cockpit-app/preview/teacher-portrait-detail`

## 用户原话

> 看看该页面有没有性能问题，总感觉进入页面加载会有卡顿。

## 现状（分析结论）

- 详情页 13 个 ECharts 图表同时初始化，每个都执行“零值 setOption → 32ms → 800ms 生长动画”，进入时 13 段动画并发。
- 图表先以空态渲染，数据到达后再次 setOption，形成重复初始化。
- 教师基本信息报告卡、年级汇总卡使用 `backdrop-filter: blur(10px)`，动画期间有额外 GPU 成本。
- DOM 较重：约 2.6MB、385 个 div、13 个 canvas。

## 目标

- 降低进入页面的首帧渲染压力与动画并发。
- 保持现有 800ms 图表入场视觉与空态/加载体验不变。
- 数据不再从三个接口获取：`getTeacherProfile` 单接口即可返回全部数据（评分趋势在 `scoreTrendList`，教师基本信息在 `teacherBasicInfo`）。

## 约束

- 不改图表视觉样式与数据契约。
- 不改列表页/教师卡片。
- 保持 `prefers-reduced-motion` 行为。

## 已验证

- 实测 `getTeacherProfile` 响应含 `scoreTrendList`（90 条）、`teacherBasicInfo`（userName/genderStr/mainSubjectName/totalClassDuration），无独立 `teachingStatistics` 字段。
- 时长由 `teacherBasicInfo.totalClassDuration` 兜底，教案数由 `myLessonPlan.totalCount` 兜底。
