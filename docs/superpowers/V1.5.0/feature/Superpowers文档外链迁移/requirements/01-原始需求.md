# Superpowers 文档外链迁移 · 原始需求

**日期：** 2026-07-29  
**分类：** feature  
**提出方式：** `/harness`

## 需求原文

把 `docs/superpowers` 这整个文件夹下的所有内容都迁移到别的仓库，单独管理文档，可以减小当前仓库体积，然后用一个外链链接就行，有什么方案。

## 目标

1. 将 `docs/superpowers/` 从本前端仓库剥离，改由独立文档仓库管理
2. 本仓库通过外链（junction / submodule / 其他）继续能读到文档，保证 Harness / Agent 工作流可用
3. 减小当前 `frontend` 仓库体积（含 clone / checkout 成本）

## 约束与现状（调研摘要）

- 当前 `docs/superpowers` 约 400+ 文件、工作区内容约 1～2 MB 量级（体积收益可能有限，需结合「是否清理 git 历史」评估）
- `scripts/harness/*`、`create-demand`、`AGENTS.md`、Cursor skills 等多处硬编码或约定路径 `docs/superpowers/`
- 本仓库已有外链先例：`.agents/skills`、`.cursor/skills` 部分通过 **JUNCTION** 指向 `E:\code\frontend-local`
- `current-version.txt` 指向 `V1.5.0`；历史版本目录含 `v1.0` / `v1.4.8` / `V1.4.9`

## 成功标准（待方案确认后写入 spec）

- Agent / harness 仍能按 `docs/superpowers/current/...` 约定读写
- 本仓库不再（或极少）跟踪文档正文 blob
- 外链方式有明确团队文档（clone / 新机器 setup）

## 待澄清

- 外链技术选型（submodule / subtree / junction / sparse）
- 是否需要清理本仓库 git 历史以真正缩小 `.git`
- 新文档仓库的托管位置与权限
