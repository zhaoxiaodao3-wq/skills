## 1. 背景

教职工岗位管理页面（`faculty-position.vue`）当前的"分配岗位"弹框只支持选岗位、提交保存。本期在已有弹框流程上**新增【数据权限】维度**，让每个教职工岗位的"管辖范围"不再模糊。

数据权限枚举共 **6 种**（产品已规划）：

| # | 数据权限枚举 | 说明 |
|---|-------------|------|
| 1 | **校区** | 仅按所选校区限定权限（**本期唯一实现**） |
| 2 | 校区 + 年级 + 科目 | 待后续 |
| 3 | 校区 + 班级 + 科目 | 待后续 |
| 4 | 校区 + 班级 | 待后续 |
| 5 | 校区 + 年级 | 待后续 |
| 6 | 校区 + 学段 + 科目 | 待后续 |

> 本期**只交付【校区】型**。其它 5 种在 spec/plan 中**留扩展点**但不实现；列表展示与交互约束要兼容后续扩展。

## 2. 业务流程（按图1～图4 整理）

### 2.1 图1 · 分配岗位（第一步 · 新增路径）

- 弹框标题：`分配岗位`
- 字段：
  - `* 选择岗位` — 下拉框，必填（已有逻辑）
  - `* 数据权限` — **新增**，单选下拉框，必填，默认"请选择"
- 操作：
  - 数据权限下拉项 = 该**岗位配置的数据权限枚举列表**，**排除【全量】**
  - 选完数据权限 → 点【下一步】→ 进入图2 弹框
  - 点【取消】→ 关闭图1 弹框

### 2.2 图2 · 数据权限详情（第二步 · 新增路径 · 校区型）

- 弹框标题：`[校区] 权限`
- 字段：`* 请选择管辖校区` — 多选 checkbox 组，必填
- 数据源：**该学校的校区列表**（mock）
- 操作：
  - 点【取消】→ 图1、图2 全部关闭
  - 点【上一步】→ 返回图1，并保留已选的数据权限
  - 点【确定】：
    - **成功**：toast 成功 → 关闭所有弹框 → 刷新岗位列表
    - **失败**：toast 失败原因 → **不**关闭弹框，用户可改后再提交

### 2.3 图2 · 重复分配规则（手动分配）

| 列表中是否已存在该岗位 | 数据权限枚举是否相同 | 行为 |
|----------------------|---------------------|------|
| 否（未分配） | — | 成功 |
| 是（已分配） | 相同 | toast `该岗位已存在且数据权限相同`，**不关闭弹框** |
| 是（已分配） | 不同 | 成功（提示 `分配成功`），关闭弹框并刷新 |

> **关键约束：** 同一岗位 + 不同数据权限枚举 → **各自单独一行**展示在列表中（列表结构约束，不只是样式）。

### 2.4 图3 · 列表展示（教职工岗位管理 · 主表）

> 代码已存在的列表（`faculty-position.vue` line 26-60），本期**不重写整张表**，只调整【权限范围】和【操作】两列。

- 字段（保留原列序）：`序号 | 岗位名称 | 岗位状态 | 权限范围 | 所属校区 | 任教科目 | 分配方式 | 操作`
- 关键渲染（本期改动点）：
  - **权限范围**：代码已是 `AppTagClampTooltip :limit="2"` + `formatter="name"`，与图3 "最多 2 + `...` + hover 弹全部" **完全匹配**，不动。
  - **所属校区**：原代码只显示 `row.campusName` 字符串。本期**改造为**：列表 ≤2 时直接展示全部；>2 时按 `,` 切，**最多展示 2 个 + `...`**；hover 弹全部。**复用** `AppTagClampTooltip`。
  - **任教科目**：当前数据权限 = `校区`（本期唯一实现）→ 显示 **"全部"**；其它 5 种数据权限 → 待扩展，本期不实现。**不加 tooltip 解释**。
  - **分配方式**：已有列（`prop="methodStr"`），**本期不动**。

#### 2.4.1 【操作】列按钮规则（**本期关键约束**）

按行是否带数据权限枚举（`row.dataPermissionEnum` 是否有值），分两种显示：

| 行类型 | 判定 | 显示的按钮（共 3 列） | disabled 规则 |
|--------|------|----------------------|---------------|
| **新增行**（带数据权限枚举，即 6 种之一） | `row.dataPermissionEnum` 真值 | `数据权限` + `删除`（**仅 2 个按钮**，无班级/科目权限） | 删除：`row.state === 1` 禁；数据权限：永远可点 |
| **原有行**（不带数据权限枚举，自动分配或预存在） | `!row.dataPermissionEnum` | `班级权限` + `科目权限` + `删除`（**保持原 3 按钮**，无数据权限） | 班级/科目：`row.method === 'auto' \|\| row.topSign === 1` 禁；删除：`row.state === 1` 禁 |

> **为什么这样设计：** 数据权限的 6 种枚举（校区 / 校区+年级+科目 / 校区+班级+科目 / 校区+班级 / 校区+年级 / 校区+学段+科目）都是**手动分配**的产物，跟原有的"自动分配 + 班级/科目权限"是两套独立流程。**两种行的"按钮集合"互斥**，避免给新增数据权限行多余的按钮。

#### 2.4.2 表单状态生命周期（**关键约束** — 防数据串台）

##### A. 图1 表单（`singleAssignForm.form`）：岗位 + 数据权限

| 时机 | 是否保留 | 备注 |
|------|---------|------|
| 点击【下一步】（图1 → 图2） | ✅ **保留**（`skipNextResetFlag = true`） | 让【上一步】能回填 |
| 点击【上一步】（图2 → 图1） | ✅ **保留** | 由 skipNextResetFlag 控制 |
| 点击【确定】（图2 提交成功） | ❌ **重置**（`resetSingleAssignForm()`） | 完成后表是干净的 |
| 点击【取消】/ X / Esc / 遮罩（图1 关闭） | ❌ **重置**（`@close` 走默认分支） | 关闭即清理 |
| **点击【分配岗位】按钮（页面级，再次打开图1）** | ❌ **必须重置** | 每次"分配岗位"都是新会话 |
| 分配成功后再次点【分配岗位】 | ❌ 重置 | 同上 |

##### B. 图2 / 图4 校区多选（`CampusMultiPickerDialog.selected`）：校区 checkbox

| 时机 | 是否保留 | 备注 |
|------|---------|------|
| 点击【下一步】（图1 → 图2） | ❌ **重置**（从 `defaultCampusIds` 重置；新增路径 `defaultCampusIds = []`） | 每次进图2 都按 `defaultCampusIds` 重来 |
| 点击【上一步】（图2 → 图1）后再次【下一步】（图1 → 图2） | ✅ **保留**（`skipResetOnOpen = true`） | 上一步/下一步是成对来回 |
| 点击【确定】（图2 成功） | ❌ 重置 + 关闭 | 成功后是干净会话 |
| 点击【取消】/ X / Esc / 遮罩（图2 关闭） | ❌ 重置（下次打开即从 defaultCampusIds 重来） | 关闭即清理 |
| **点击列表行【数据权限】按钮（编辑路径 → 图4）** | ❌ **必须重置**（从当前行的 `scopeCampusIds` 重置） | **每次"数据权限"都是新会话** |
| 编辑某行 → 修改选中 → 取消（不保存）→ 再点【数据权限】（同一行） | ❌ 必须重置 | **不展示用户修改过没保存的选中** |

##### C. 编辑上下文（`editingRow`）

| 时机 | 是否清空 | 备注 |
|------|---------|------|
| 点击【分配岗位】按钮 | ✅ **必须清空**（`editingRow = null`） | 否则默认 `defaultCampusIds` 仍是旧行 → 图2 错位 |
| 点击【确定】（图2 编辑成功） | ✅ 清空 | `editingRow = null` |
| 点击【取消】/ X / Esc / 遮罩（图4 关闭） | ❌ 保留（下次再开同一行仍是它） | 由 defaultCampusIds 决定显示 |

> **核心原则（综合 A + B + C）：**
> - **保留** 只发生在"图1 ↔ 图2 的成对来回"里（`skipNextResetFlag` + `skipResetOnOpen` 双标志守住边界）
> - **重置** 发生在所有"页面级 / 列表级 / 弹框关闭级"事件：分配岗位按钮 / 数据权限按钮 / 成功完成 / 主动取消
> - **重置的源头**永远是 `defaultCampusIds`（新增路径 [] / 编辑路径 行.scopeCampusIds），**绝不缓存"用户修改未保存"的值**

- 学年升级处理（**仅校区型**特殊，其他 5 种后续）：
  - 升级后，每条岗位数据的年级/班级/科目都要同步升级
  - 但**【校区】型**不涉及升级（权限范围是校区，不带年级；任教科目是"全部"，无需处理）

### 2.5 图4 · 数据权限编辑（从列表进入 · 编辑路径）

- 入口：列表行的【数据权限】操作
- 弹框标题：`[校区] 权限`

  - 点【取消】→ 仅关本弹框

- 与图2 的差异：**没有【上一步】按钮**（编辑路径不回第一步）
