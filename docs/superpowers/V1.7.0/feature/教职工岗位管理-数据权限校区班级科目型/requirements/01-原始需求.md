## 3. 业务流程

### 3.1 图1 · 分配岗位

- 字段：`*选择岗位` + `*数据权限` +（当枚举=`campus_class_sub` 时）`设置方式` 单选同一行  
  - 选项：`one_to_one`「班级科目1对1设置」（默认） / `many_to_many`「班级科目多对多设置」
- 数据权限：岗位配置枚举，排除全量
- 【下一步】分支：
  - `one_to_one` → 打开本类型图2（五级多行弹框）
  - `many_to_many` → **关闭图1（或按现有交互）并打开原有班级权限弹窗**；不进入本类型图2
- 【取消】关图1

### 3.2 图2 · 1对1 详情（新增路径）

- 标题：`【校区+班级+科目】权限`
- 多行五级级联；默认 1 空行；+/-；滚动；至少 1 行
- 取消关两层；上一步回图1（保留岗位、数据权限、**设置方式**）
- 确定：成功/失败同前两型；岗位级重复见 §4

### 3.3 级联

- 路径：`校区 → 学段 → 年级 → 班级 → 科目`
- 单选叶子；当前学年；`ElCascader`；数据 mock

### 3.4 行内判重

- `pathKey = campusId + stageId + gradeId + classId + subjectId`（五段）
- 冲突 → toast「科目已存在」，不请求

### 3.5 列表（1对1 行 / 带本枚举行）

| 列 | 规则 |
|----|------|
| 权限范围 | **班级**并集；limit=2 + hover |
| 所属校区 | 校区去重并集；limit=2 |
| 任教科目 | 科目去重并集；limit=2 |
| 操作 | 数据权限 + 删除 |

> 多对多若落成「无 dataPermissionEnum 的原有行」或带标记行：操作列仍走原有班级/科目权限按钮规则；**本期不改造多对多落库形态**（沿用现有班级权限保存结果）。

### 3.6 图4 · 编辑（仅 1对1 行）

- 无上一步；回填 `scopePaths`；取消/确定同 CGS

### 3.7 表单生命周期

- 沿用三层守门；本 kind 分槽 `skipResetByKind.campus_class_sub`
- 设置方式随图1 表单：成对上一步/下一步保留；新开会话重置为默认 1对1

## 5. 工程要求

1. 组件：`data-permission/campus-class-subject/`（cascader + picker-dialog，kebab 四件套）
2. registry 注册 strategy；`DATA_PERMISSION_IMPLEMENTED` 纳入 `CAMPUS_CLASS_SUB`
3. 图1：条件渲染设置方式；`openNext` 按 setupMode 分支（1对1 → session.open kind；多对多 → `addUpdateClass` / 等价现有入口）
4. 多对多下一步时需先完成「分配岗位」还是先开班级权限？  
   → **P1 默认：** 多对多 = 用户已选岗位后下一步直接打开班级权限弹窗（与「给该岗位配班级」现网一致）；若必须先调 assign 再开班级窗，实现前再与产品对齐。**暂定：下一步打开班级权限弹窗，岗位上下文传入现有 dialog 所需 data**（与现 `addUpdateClass(row)` 对齐；若尚无 row，则先 mock/真接口创建一个「多对多」占位行再打开——**待实现探查现网「分配后开班级」顺序**；若探查为「必须已有列表行」，则多对多下一步 = 先 assign(setupMode=many_to_many, scopes=[]) 成功再 `openClassDialog(newRow)`）。

> **实现前探查结论写入 spec：** 读 `SelectClassListDialog` 入参，定多对多次序，避免臆造。

5. 学年升级不写；对接说明在交付时补 mock 清理项
