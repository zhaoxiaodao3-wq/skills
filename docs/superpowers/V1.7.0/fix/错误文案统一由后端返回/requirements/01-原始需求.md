# 原始需求：所有错误/警告提示统一由后端返回具体文案

## 业务背景

数据权限分配流程中，前端调 `saveSchoolTenantUserPost` / `facultyAssignPost` / `updateDataScope` 等接口时，根据后端响应码分支展示 toast：

| 响应码 | 含义 | 当前前端 hardcode 文案 |
|--------|------|---------------------|
| `OK` | 成功 | `"分配成功"` / `"保存成功"` |
| `ALREADY_EXISTS` | 重复分配（数据权限相同） | `"该岗位已存在且数据权限相同"` |
| 其他 | 失败 | 兜底 `"分配失败"` / `"保存失败"` / `"操作失败"` |

## 业务诉求

- **所有错误/警告提示**统一由后端在 `res.message` 字段返回具体文案
- 前端**只展示 `res.message`**，不做文案翻译/拼接
- 后端保证：调用失败时，`res.message` 必有具体可读文案
- 前端 hardcode 仅作为兜底（防后端漏返 message 时显示空白 toast）

## 适用范围

| 流程 | 调用的接口 | 涉及的提示分支 |
|------|-----------|---------------|
| 分配（1对1） | `saveSchoolTenantUserPost`（通过 `facultyAssignPost`） | OK / ALREADY_EXISTS / 失败 |
| 分配（CCS 多对多） | `saveSchoolTenantUserPost`（多对多占位 + 班级窗二次提交） | ALREADY_EXISTS / 失败 |
| 编辑（1对1） | `updateDataScope`（通过 `facultyUpdateDataPermission`） | OK / 失败 |

## 关键代码位置

- `src/composables/useFacultyDataPermissionSession.ts`
  - `openManyToManyClassPermission`（多对多分配） line 154-200
  - `onDetailSubmit`（1对1 分配 + 编辑提交） line 383-435

## 关联契约

接口文档 `saveSchoolTenantUserPost` / `updateDataScope` 需补充：
- 响应字段约定：`code` + `message`
- `code` 取值：`OK` / `ALREADY_EXISTS` / 其他错误码
- `message`：失败/警告时必有；前端直接展示

## 验收

- [ ] `ElMessage.warning` 文案统一用 `res?.message ?? 兜底文案`
- [ ] `ElMessage.error` 文案统一用 `res?.message ?? 兜底文案`
- [ ] `ElMessage.success` 文案统一用 `res?.message ?? 兜底文案`（虽然成功不算"错误"，但按"前端只展示"原则同样处理）
- [ ] 兜底文案仅作 safety net，不依赖其展示
- [ ] 接口文档（`saveSchoolTenantUserPost` / `updateDataScope`）补充 `message` 字段约定
