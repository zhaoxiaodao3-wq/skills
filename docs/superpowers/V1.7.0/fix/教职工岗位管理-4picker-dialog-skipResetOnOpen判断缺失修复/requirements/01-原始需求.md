# 教职工岗位管理-4picker-dialog-skipResetOnOpen判断缺失修复

> 模块版本：V1.7.0 / fix
> 模式：hotfix
> 修复日期：2026-09-23

## 1. 背景

紧接 `fix/教职工岗位管理-CGS_CCS_CSE-baseGradeId字段修复` DELIVERED 之后，用户实测反馈：

> "上一步下一步弹窗切换的时候，之前不是说过，除非是重新点击分配岗位，也就是新增，才清空表单吗，其他的应该是保留的，现在怎么我点上一步，再点下一步，原来的内容都清空了"

## 2. 真实根因（源码确认）

父组件 `useFacultyDataPermissionSession` 的 `prevStep()` 函数：
```ts
async function prevStep() {
  const kind = activeKind.value
  if (!kind) return
  setSkip(kind, true)  // ← 设 skip=true，下次打开不重置
  ...
}
```

父组件在 `faculty-position.vue` 把 `:skip-reset-on-open="skipResetByKind.xxx"` 正确传给 **5 个** picker-dialog。

**但是 4 个 picker-dialog（CGS / CCS / CC / CSE）的 watch 完全没读 `props.skipResetOnOpen`**：

| picker-dialog | watch `if (!props.skipResetOnOpen)` 判断 |
|---|---|
| `campus-grade-picker-dialog.vue` | ✅ **有**（line 99） |
| `campus-grade-subject-picker-dialog.vue` | ❌ **漏写**（line 105） |
| `campus-class-picker-dialog.vue` | ❌ **漏写**（line 113） |
| `campus-class-subject-picker-dialog.vue` | ❌ **漏写**（line 113） |
| `campus-stage-subject-picker-dialog.vue` | ❌ **漏写**（line 105） |

只有 CG picker-dialog 有 skip 检查，其余 4 个 picker-dialog 始终无条件 `rows.value = initScopes(props.defaultScopes)`。

## 3. 业务影响

| 场景 | CG | CGS / CCS / CC / CSE |
|---|---|---|
| 编辑模式打开 → 选 → 上一步 → 下一步 | rows 保留 ✓ | **rows 被 initScopes 重置** ✗ |
| 新增模式打开 → 选 → 上一步 → 下一步 | rows 保留 ✓ | **rows 被 initScopes 重置** ✗ |
| 跨 kind 切换（CG → CGS） | 各自重置（符合预期）✓ | 各自重置 ✓ |

**CG 行为正确**，**CGS / CCS / CC / CSE 4 个 picker-dialog 行为错误**——用户已选的内容在上一步→下一步时被清空，体验问题 + 可能误提交。

## 4. 修复方案

直接 hotfix：4 个 picker-dialog 的 watch 各加一行 `if (!props.skipResetOnOpen)` 判断，与 CG picker-dialog 对齐。

```ts
watch(
  () => props.modelValue,
  (open) => {
    if (!open) return
    // 父组件 prevStep 设 skip=true 后，重新打开时不重置 rows
    if (!props.skipResetOnOpen)
      rows.value = initScopes(props.defaultScopes ?? [])
  },
)
```
