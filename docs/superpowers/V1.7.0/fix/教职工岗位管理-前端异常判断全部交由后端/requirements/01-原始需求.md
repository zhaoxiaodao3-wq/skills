## 3. 保留的位置（不是"业务校验异常"）

| 位置 | 用途 | 原因 |
|------|------|------|
| composable 各种 `ElMessage.success(res?.message ?? 'xxx')` | 展示后端 message + fallback | 后端权威 |
| composable 各种 `ElMessage.error(res?.message ?? 'xxx')` | 展示后端 message + fallback | 后端权威 |
| composable `catch` 块 `ElMessage.error(e?.message ?? '操作失败')` | 网络/代码异常兜底 | 真正的兜底 |
| composable L192 `'分配异常，请重试'` | 分配占位 row 拿不到（前端流程问题） | 结构性，不是"业务异常" |
| picker-dialog `canRemoveRow` | 行数 UX 限制 | 不是"异常判断" |

## 4. 修复

### 4.1 5 个 util 的 validateScopes → filterScopes

删除 `ok` / `message` 字段，只保留"过滤 null 行"逻辑：

```ts
/**
 * 过滤 null 行：返回非空 scopes（供后端校验）
 * 前端不做段数完整性 / 重复校验，全部由后端判断并返回 message
 */
export function filterScopes(scopes: ScopeRow[]): SchoolFacultyPermissionScopeDTO[] {
  return scopes.filter((row): row is SchoolFacultyPermissionScopeDTO => row !== null)
}
```

### 4.2 5 个 picker-dialog 的 onSubmit

直接 emit submit 给后端，**删除** `validateScopes` 调用 + `ElMessage.warning`：

```ts
function onSubmit() {
  // 前端不做异常判断：段数完整性 / 重复 / 数据权限类型，全部由后端校验并返回 message
  submitLoading.value = true
  emit('submit', filterScopes(rows.value))
  setTimeout(() => {
    submitLoading.value = false
  }, 300)
}
```

### 4.3 composable 4 处 warning

保留 enum / kind 防御逻辑（不向后端发无效请求），但**删除 warning 提示**：

```ts
// openNextFromFigure1
if (!form.tenantPostId || !form.dataPermissionType) {
  return  // 防御：未选岗位/数据权限不向后端发请求
}
const strategy = resolveDataPermissionStrategy(form.dataPermissionType)
if (!strategy) {
  return  // 防御：未知 enum 不向后端发请求
}

// openEdit
const strategy = resolveDataPermissionStrategy(readType(row) ?? '')
if (!strategy) {
  return  // 防御：未知 enum 不向后端发请求
}

// onDetailSubmit
if (!strategy || detail.kind !== strategy.kind) {
  return  // 防御：未知 enum / kind 不匹配不向后端发请求
}
```
