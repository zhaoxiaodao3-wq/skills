# 教职工岗位管理-CCS多对多分配班级弹窗丢失下一步链路修复

> 模块版本：V1.7.0 / fix
> 模式：标准档（bug 修复 + 链路补齐）
> 修复日期：2026-09-24

## 1. 背景

用户实测反馈（分配岗位 → 选「校区+班级+科目」+「多对多设置」→ 下一步）：

> "分配岗位班级科目多对多设置的弹窗选择完班级好像还有下一步科目弹窗设置，现在怎么直接在班级弹窗就直接确定了，你查看归档的内容，原来的逻辑链路是完全不需要动的"

## 2. 期望链路（恢复 84b8d87 设计）

```
[分配岗位] → 图1(岗位 + CCS + MANY_TO_MANY) → 下一步
   ↓ facultyAssignPost({classIds:[], subjectIds:[]}) 创建占位行
班级弹窗 [singleMode=true] 
   ├─ 「上一步」 → 回图1（占位行回滚）
   └─ 「下一步」 → 调 onNext({...data, classIds, classList})
                    ↓
                 科目弹窗 [singleMode=true]（继承自 data）
                    ├─ 「上一步」 → 重开班级弹窗（保留 classList 选中）
                    └─ 「提交」 → updateFacultyPermission({id, classIds, subjectIds}) 落库
                                  ↓ submit-success
                                onClassListSubmitSuccess → 刷列表
```

## 3. 真实根因（源码确认）

`6800a3a`（9月18日「feat(faculty): 新增数据权限相关组件和工具」）重构 picker-dialog 时，把 `84b8d87` 的三步链路替换成新架构，但新架构里**忘了把 `singleMode: true` + `onNext` 传给班级弹窗**。

### 3.1 session 调用班级弹窗时数据不全

`useFacultyDataPermissionSession.openManyToManyClassPermission` 创建占位行后调用 `openClassPermissionDialog(row)`：

```ts
// 变更前 ❌
const row = newId ? {
  id: newId,
  dataPermissionType: DataPermissionEnum.CAMPUS_CLASS_SUBJECT,
  setupMode: DataPermissionSetupMode.MANY_TO_MANY,
  classList: [],
  subjectList: [],
} : null
options.openClassPermissionDialog(row)  // ← 缺 singleMode / onNext
```

而 `SelectClassListDialog.vue:88` footer 按钮分支判断：

```vue
<template v-if="data?.batchMode === true || data?.singleMode === true">
  <ElButton @click="handleBack">上一步</ElButton>
  <ElButton @click="handleAssignSubmit">下一步</ElButton>
</template>
<ElButton v-else @click="handleSubmit">确定</ElButton>
```

`singleMode` 不是 true → 走「确定」分支 → 触发 `handleSubmit()`：

```ts
if (props.data?.id) {
  await service.school.updateFacultyPermission({
    id: props.data?.id,
    ...params.value,  // classIds=已选, subjectIds=[] (空)
  })
  ElMessage.success('编辑成功')
  emit('submit-success')
  modelVisible.value = false
}
```

`subjectIds` 永远是空、**科目弹窗从未弹出**。

### 3.2 页面侧 `subjectListForAssignDialog` 是死代码

`faculty-position.vue:189` 模板已经绑定了 `<select-subject-list-dialog v-model:visible="subjectListForAssignDialog.visible">`，但：
- `subjectListForAssignDialog` reactive 仅声明、从未被 `visible = true`
- `useFacultyDataPermissionSession` 没有 `openSubjectPermissionDialog` option

也就是「占位行 commit + 科目弹窗接力」这条链路在新架构里**完全没接通**。

### 3.3 `SelectSubjectListDialog.handleSingleSubmit` 用错接口

`singleMode=true` 路径调用 `saveSchoolTenantUserPost({tenantPostId, tenantUserId, ...})` 创建新行；但新架构已有占位行（`id`），应当走 `updateFacultyPermission({id, classIds, subjectIds})` 补齐数据。

## 4. 业务影响

| 场景 | 变更前 | 变更后 |
|---|---|---|
| 图1 → CCS MANY_TO_MANY → 下一步 | 班级弹窗只显示「确定」按钮 | 显示「上一步」「下一步」按钮 |
| 班级弹窗选完班级 → 点击 | 直接 `updateFacultyPermission({id, classIds, subjectIds: []})` 落库空科目 | 弹出科目弹窗 |
| 科目弹窗选完 → 点击 | 弹窗不弹 | 「提交」落库 `updateFacultyPermission({id, classIds, subjectIds})` |
| 班级/科目整个链路是否能完成 | ❌ 始终空 subjectIds | ✅ 与 84b8d87 一致 |
| 班级弹窗「上一步」回图1 | 无 onBack | setFigure1Visible(true) + 占位行回滚 |
| 科目弹窗「上一步」回班级 | 无 onBack | 重开班级弹窗、保留 classList 选中 |

## 5. 修复方案

最小改动接通 3 步链路，**不动 picker-dialog 体系、不动 1对1 / CGS / CC / CG / CSE 路径**：

1. **session**: `openManyToManyClassPermission` 调用班级弹窗时传 `singleMode: true + onBack + onNext`；新增 `openSubjectPermissionDialog` option；加 `manyToManyGoingToNext` 标记防班级关闭时误回滚占位行
2. **faculty-position.vue**: 注入 `openSubjectPermissionDialog` 接上 `subjectListForAssignDialog`；`submit-success` 接到 `onClassListSubmitSuccess`；加 `subjectListGoingBack` + `onSubjectListVisible` 处理科目弹窗「上一步」不触发回滚；`handleSinglePosition` 重置 CCS 中间态
3. **SelectClassListDialog.vue**: `handleAssignSubmit` **先调 onNext、再 emit update:visible(false)** —— 必须先告诉父级「正在切下一步」，否则父级在班级关闭时检测不到标记会回滚占位
4. **SelectSubjectListDialog.vue**: `handleSingleSubmit` 在 `data.id` 存在（占位行场景）时走 `updateFacultyPermission`；无 id 时仍走 `saveSchoolTenantUserPost` 兼容老 `faculty/index.vue` 的批量流程（不破坏）

## 6. 验收口径

- ✅ 班级弹窗 footer 在 CCS MANY_TO_MANY 路径显示「上一步」「下一步」按钮（不再显示「确定」）
- ✅ 班级弹窗「下一步」→ 弹出科目弹窗；subjectIds 不再为空
- ✅ 科目弹窗「提交」→ `updateFacultyPermission({id, classIds, subjectIds})` 落库 → 刷新列表
- ✅ 班级弹窗「上一步」→ 回图 1 + 占位行回滚（与现有 cancel 行为一致）
- ✅ 科目弹窗「上一步」→ 重开班级弹窗、保留 classList 选中、不回滚占位
- ✅ 班级/科目任一取消 → 占位行回滚
- ✅ 1对1 / CGS / CC / CG / CSE 路径不受影响（picker-dialog 体系零改动）
- ✅ `faculty/index.vue` 批量流程不受影响（`batchMode=true` 不变）
- ✅ `vue-tsc --noEmit` EXIT 0
