# 教职工岗位管理-picker-dialog-关闭时清空内部状态

> 模块版本：V1.7.0 / fix
> 模式：hotfix
> 修复日期：2026-09-23

## 1. 背景

紧接 `fix/教职工岗位管理-前端异常判断全部交由后端` DELIVERED 之后，用户实测反馈：

> "再仔细检查一下，我发现我选择校区类型的时候，选了某个管辖校区，关闭所有弹窗，第二次再从新走创建流程，还是记录了上次选中的内容，这不对，其他类型也检查"

## 2. 真实根因

`CampusMultiPickerDialog` 和 5 个 picker-dialog 的 `watch(() => props.modelValue)` 在 `!open`（关闭）时**只 return，不清空内部状态**（selected / rows），**第二次走创建流程时 race condition 导致 picker-dialog 保留上次选的内容**。

### 2.1 CampusMultiPickerDialog 当前 watch

```ts
watch(
  () => props.modelValue,
  async (open) => {
    if (!open)
      return  // ← 不清空 selected
    const list = await service.school.facultyCampusList(props.schoolId)
    ...
    if (!props.skipResetOnOpen) {
      selected.value = [...props.defaultCampusIds]
    }
  },
  { immediate: true },
)
```

### 2.2 5 个 picker-dialog 当前 watch

```ts
watch(() => props.modelValue, (open) => {
  if (!open)
    return  // ← 不清空 rows
  if (!props.skipResetOnOpen)
    rows.value = initScopes(props.defaultScopes ?? [])
})
```

### 2.3 race condition 触发路径

第二次走创建流程时，`watch(open=true)` 应该按 defaultScopes 重置，但实际有以下 race：

| 时序 | 状态 |
|---|---|
| 关闭 picker-dialog → watch(open=false) | selected 保留 |
| `beginAssignSession` → `resetAllSkip()` → skip=false | — |
| 用户选类型 → 点"下一步" → `campusVisible=true` | — |
| picker-dialog watch(open=true) 触发 | 理论上 reset selected = [] |
| **但**：可能 `props.defaultCampusIds` 是**同一引用**（computed 缓存）→ watch 不触发 → **selected 保留上次值** |

或：

| 时序 | 状态 |
|---|---|
| picker-dialog watch(open=true) 触发 | 进入 await fetchCampusList |
| 父组件 setFigure1Visible(false) 触发 → 图1 关闭 |
| 用户立刻关 picker-dialog → watch(open=false) return（**不清空 selected**） |
| `await fetchCampusList` 完成 → `if (!skip) selected = [...defaultCampusIds]` → 写入上次值 |

无论哪种 race，最终结果都是**picker-dialog 内部状态保留上次内容**。

### 2.4 防御层缺失：composable 的 onDetailClosed 不调 setSkip(false)

```ts
function onDetailClosed(kind: DetailDialogKind) {
  if (activeKind.value !== kind) return
  activeKind.value = null
  ...
  // ❌ 缺：setSkip(kind, false)
  if (!editingRow.value) {
    options.setFigure1Visible(false)
    options.resetFigure1()
  }
}
```

`beginAssignSession` 有 `resetAllSkip()` 但 closeAllDetails 路径没显式 `setSkip(false)`——理论上 beginAssignSession 会重置，但 race 期间可能 skip 还是 true。

## 3. 业务影响

| 场景 | 变更前 | 变更后 |
|---|---|---|
| 校区类型 picker-dialog：选 A → 关弹窗 → 重新点分配岗位 → 选 campus 类型 → 进 picker-dialog | **仍显示 A** ✗ | **空** ✓ |
| CGS/CCS/CC/CSE：选 scope → 关弹窗 → 重新走创建 | **仍显示上次 scope** ✗ | **空** ✓ |
| 编辑模式打开 picker-dialog → 选 → 上一步 → 下一步（prevStep 设 skip=true） | rows 保留 ✓ | rows 保留 ✓（按 `skipResetOnOpen=true` 跳过 reset） |
| 提交成功后 → closeAllDetails → 重走创建 | selected 清空 ✓ | selected 清空 ✓ |

## 4. 修复方案（双层防御）

### 4.1 picker-dialog 关闭时立即清空内部状态

```ts
// CampusMultiPickerDialog
watch(() => props.modelValue, async (open) => {
  if (!open) {
    selected.value = []  // ← 新增：关闭时清空
    return
  }
  ...
})

// 5 个 picker-dialog
watch(() => props.modelValue, (open) => {
  if (!open) {
    rows.value = [null]  // ← 新增：关闭时清空
    return
  }
  ...
})
```

### 4.2 composable onDetailClosed 显式 setSkip(kind, false)

```ts
function onDetailClosed(kind: DetailDialogKind) {
  if (activeKind.value !== kind) return
  activeKind.value = null
  ...
  // 防御：保证关闭详情时显式把 skip 设回 false，
  // 防止 race condition 导致第二次走创建流程时残留上次内容
  setSkip(kind, false)  // ← 新增
  if (!editingRow.value) {
    options.setFigure1Visible(false)
    options.resetFigure1()
  }
}
```

## 5. 验收口径

- ✅ 6 个 picker-dialog 关闭时清空内部状态（5 个 rows + 1 个 selected）
- ✅ composable onDetailClosed 显式 setSkip(kind, false)

- ✅ prevStep 设 skip=true 行为不变（上一步 → 下一步保留 rows）
