# 教职工权限回显与保存修复 · 类型判断修正

**模块名：** api-adapter/教职工权限回显与保存修复
**版本：** V1.7.0
**日期：** 2026-09-23
**修正类型：** DELIVERED 后小修正(单行判断逻辑)

---

## 1. 修正原因

DELIVERED 后用户反馈:`dataPermissionType === 'campus_class'`(CC 类型)点击【数据权限】打开了"班级权限"老弹框,而不是 CC picker-dialog。同样的问题影响其他所有非 CCS 类型。

## 2. 原错误逻辑(T4)

`src/composables/useFacultyDataPermissionSession.ts:openEdit`

```ts
const isCcsOneToOne = type === DataPermissionEnum.CAMPUS_CLASS_SUBJECT
const isManyToMany = !isCcsOneToOne  // ← 错误:把所有非 CCS 都视为多对多

if (isManyToMany) {
  options.openClassPermissionDialog?.(row)
  return
}
```

**问题**:`!isCcsOneToOne` 涵盖 `campus` / `campus_class` / `campus_grade` / `campus_grade_subject` / `campus_stage_subject`,全部误判为"CCS 多对多"走老接口。

## 3. 修正后逻辑

```ts
const isLegacyManyToMany = !type  // 涵盖 undefined / ''

if (isLegacyManyToMany) {
  options.openClassPermissionDialog?.(row)
  return
}
const strategy = resolveDataPermissionStrategy(type)
if (!strategy) {
  return
}
```

**逻辑**:
- `undefined` / `''` → 走老路径(CCS 多对多 / 老的非数据权限类型)
- 其他所有 enum 值 → 走 `resolveDataPermissionStrategy` → 对应 strategy

## 4. 影响验证(逻辑分支)

| `dataPermissionType` | 修正前分支 | 修正后分支 | 期望分支 |
|---------------------|----------|----------|---------|
| `undefined` / `''` / `null` | 老路径 | 老路径 | 老路径 ✓ |
| `campus` | 老路径 ❌ | campusStrategy → 校区弹框 | 校区弹框 ✓ |
| `campus_class` | 老路径 ❌ | campusClassStrategy → CC picker-dialog | CC 弹框 ✓ |
| `campus_class_subject` | CCS 1对1 弹框 | CCS 1对1 弹框 | CCS 弹框 ✓ |
| `campus_grade` | 老路径 ❌ | campusGradeStrategy → CG picker-dialog | CG 弹框 ✓ |
| `campus_grade_subject` | 老路径 ❌ | campusGradeSubjectStrategy → CGS picker-dialog | CGS 弹框 ✓ |
| `campus_stage_subject` | 老路径 ❌ | campusStageSubjectStrategy → CSS picker-dialog | CSS 弹框 ✓ |

## 6. 决策一致性

D-2 用户原话:"CCS 多对多 / 1对1 区分:CCS 1对1 时 dataPermissionType='campus_class_subject';CCS 多对多为空字符串/null/老的非 1对1 值"

**澄清**:"老的非 1对1 值"指的是**老的非数据权限类型行**(UI 上没有【数据权限】按钮,显示原 3 按钮——班级 / 科目 / 删除),这些行 **不会进 openEdit**。本修正后,**所有 6 种 1对1 类型都走新接口**,与 D-2 一致。
