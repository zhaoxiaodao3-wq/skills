# 自检修复与提交三个 id · 原始需求

**日期：** 2026-09-30（第一轮交付后的复检追加）
**上游需求：** [01-原始需求.md](./01-原始需求.md)
**上游 spec：** [../specs/01-dev-spec.md](../specs/01-dev-spec.md)

## 1. 背景

第一轮（年级/学科/班级统一到学校实体数据源）已于 2026-09-30 交付并归档。复检时发现
**实现存在一处根因级缺陷，导致逻辑不闭环**，同时追加一个提交侧的新需求。

用户复检口径：**操作上要让人感觉跟原来一模一样——只是年级换成级联、班级换成下拉，
其他逻辑操作一模一样。**

## 2. 缺陷：lazyLoad 记录了错误的节点（逻辑不闭环）

### 2.1 现象

`ElCascader` 的 `lazyLoad(node, resolve)` 回调中，`node.data` 是**当前层的父节点**，
不是该层正在创建的节点。第一轮实现把 `node.data` 当成了「本层选中的节点」来记录：

```ts
// level 1（学段）分支
gradeStageNode.value = data    // data = 校区节点（学段的父节点）
// level 2（年级）分支
gradeCascaderNode.value = data // data = 学段节点（年级的父节点），params 中无 gradeInfo
```

而 `handleGradeChange` 从这两个 ref 上读取叶子实体数据，导致 4 个字段全部取错：

| 字段 | 实际取值 | 后果 |
|------|---------|------|
| `refBaseGradeId` | `params.gradeInfo?.baseGradeId` → 恒 `undefined` → `''` | `loadSubjectOptions('')` 早退，**学科下拉永远为空** |
| `refGradeNumber` | 同上 → 恒 `''` | 教材接口 `gradeLevelCode` 丢失 |
| `analysisGradeName` | `gradeNode.label` → 实为学段 `typeStr`（如"小学"） | 提交的年级名变成"小学"而非"初一" |
| `refStageId` | `stageNode.value` → 实为校区节点的 value | `schoolClassList` 拿校区 id 当 stageId 传入 |

**综合后果：学科下拉为空，整个「新增课堂」流程不可用。**

### 2.2 为什么没被现有验证拦住

- `pnpm typecheck` 全部通过（字段都是字符串，无类型冲突）
- 36 个单元测试全部通过（测试覆盖 `course-basic-data.ts` 的纯函数，而缺陷在
  Vue 组件内的响应式赋值错位，纯函数层无法暴露）
- 提交格式与残留符号检查均通过

即：**现有验证手段对"组件内字段错位"这一类缺陷是盲区**，需靠人工走查 + 浏览器联调。

### 2.3 修复方案（P1 已确认方向）

改为在每层构建 `list` 的同时维护 **id → 原始实体记录** 的映射表，`handleGradeChange`
只从映射表取年级/学段实体，只从父节点 `params` 取 `campusId` / `stageId`（这部分本就正确）。

该方案**不依赖 Element Plus 内部 API**，与 `hydrateGradeCascadePath`（回显，仍用内部 API）解耦。

## 3. 新需求：提交接口携带校区 / 学段 / 年级 id

`classRoomInsert` / `classRoomMarkUpdate` 需额外提交三个 id。

**注意与第一轮的冲突：** 第一轮在 `setOptsForm` 中把 `refCampusId` / `refStageId` / `refGradeId`
作为「纯前端辅助字段」`delete` 掉了。本轮需求是**从剔除改为改名提交**。

### 3.1 字段名（P1 决策）

| 提交字段 | 来源 | 说明 |
|---------|------|------|
| `campusId` | `form.refCampusId` | 校区 id |
| `stageId` | `form.refStageId` | 学段 id |
| `gradeId` | `form.refGradeId` | 年级 id |

与 `classRoomGetById` 返回的同名字段保持一致，使
**提交 → 后端存储 → `getById` 返回 → 前端回显** 全链路字段名自洽。

### 3.2 明确不提交的字段（P1 决策）

以下字段仅供前端调用 qbank 教材接口 / 学科学段接口使用，**不提交给后端**：

- `refStageType`（学段 `type`，仅用于教材接口 `baseEducationStageCode`）
- `refGradeNumber`（年级 `number`，仅用于教材接口 `gradeLevelCode`）
- `refBaseGradeId`（年级 `baseGradeId`，仅用于学科接口入参）

## 4. 复检中确认、但明确不改的项

### 4.1 班级字段宽度

`ElSelect` 默认 `--el-select-width:100%`（满宽），`ElCascader` 无 width 声明
（`display:inline-block` 自适应）。班级由级联换成下拉后会变宽。

**P1 决策：保留 `width:100%`。** 班级与其余 5 个字段宽度对齐；与改造前的窄宽度不同，
但窄宽度本身是原实现的疏漏，不予还原。

### 4.2 学科 / 班级对年级的依赖

改造前年级、学科、班级三者完全独立；改造后不选年级则学科与班级禁用。
这是接口依赖的内在要求（学科需 `baseGradeId`+`stageId`，班级需 `campusId`+`stageId`+`gradeId`），
**属于需求带来的必要变化，不予还原**。

### 4.3 历史课堂（缺三个 id）的保存边界

`refGradeId` 是必填校验项，故历史课堂级联留空时**无法保存**，用户必须重选年级；
重选后 `analysisGradeName` 由 `handleGradeChange` 覆盖为正确年级名。
因此第一轮 spec §9.2 所述「级联空但名称有值导致年级班级不一致」的风险**实际不会发生**，
原「回退方案」不需要启用。

## 5. 范围约束

- 只改 `src/pages/course/components/CreateCourseDialog.vue`
- 教材章节接口、核心教案、授课工具、列表页逻辑一律不动（同第一轮 spec §10）
