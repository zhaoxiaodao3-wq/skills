# 学科/班级间歇性不请求（第二次反馈）· 原始需求

**日期：** 2026-09-30（v3 交付后的联调反馈，第 2 轮）
**上游需求：** [03-学科班级不随年级重新查询.md](./03-学科班级不随年级重新查询.md)
**上游 spec：** [../specs/01-dev-spec.md](../specs/01-dev-spec.md)

## 1. 用户反馈

> 「这个选择不同年级之后请求学科和班级的逻辑你到底是怎么写的，我现在切换来切换去就突然不请求学科和班级了」

## 2. 定位结论

v3 修复后仍复现，且特征是**「切换来切换去就突然不请求」**——操作若干次后稳定失效，
不是首次选择就失效（那已被 v3 缺陷 A 覆盖）。

### 2.1 问题 1：v2 的受控改造引入了状态错位（我方回归）

v2「缺陷 2」把级联从 `v-model` 改成 `:model-value` 受控，理由是避免
`v-model` 与 `@change` 双写 `refGradeId`。**该改造本身有硬缺陷：**

受控组件要求父组件回写值，而当时只接了 `@change`、**未接 `@update:modelValue`**。
后果链条：

1. 用户点击**校区 / 学段**等非叶子节点 → Element Plus 清掉已选叶子并发出 `change`，
   值为 `undefined`
2. `handleGradeChange` 的 `typeof gradeValue === 'string' ? gradeValue : ''`
   判定为 `''` → 走进**清空分支** → `refGradeId` 被写成 `''`
3. `''` 回写给受控组件 → 级联内部 store 与外部值错位
4. 之后的选择不再产生有效 `change` → **学科/班级请求彻底停止**

「切换来切换去就突然不请求」与该链条完全吻合。**受控改造是判断失误，应回退。**

### 2.2 问题 2：只切校区/学段、不重选年级时，旧选项不重置

重置 watch 监听 `[refCampusId, refStageId, refGradeId]`，而这三个字段
**只在选中叶子年级时才被写**。用户换了校区、学段但未点年级时 watch 不触发，
上一个年级的学科与班级选项继续留在下拉里——**业务上是错的**（选项所属年级与当前级联不符）。

### 2.3 共同根源

两处都源于「**不直接从级联拿到完整选中路径，而是从父节点 `params` 反推 id**」：

- `gradeCascaderNode.value.params.stageId` / `.campusId` 依赖「哪一层的 lazyLoad 最后执行过」
  （v2 缺陷 1 的同类问题，虽已用映射表绕开实体字段，但 id 仍走父节点）
- `emitPath: false` + 受控组合，丢失了「校区/学段已变但年级未变」这一可观测信号

## 3. 修法（P1 决策：按完整路径重写）

**去掉 `emitPath: false`，使用级联的完整选中路径。**

```
change(['校区id', '学段id', '年级id'])  →  三级 id 一次拿全 → 取实体 → 重置 → 加载学科/班级
change(['校区id', '学段id'])            →  只切了校区/学段 → 只重置，不加载
change(null / [])                      →  清空 → 清空全部
```

同时：

- 级联**改回 `v-model`**（绑定路径数组），不使用受控写法
- **删除重置 watch**，`handleGradeChange` 成为唯一触发点
- **删除 `gradeCascaderNode`**（新方案下不再需要从父节点反推 id）

一次消除四类问题：

1. 不再依赖「哪一层的 lazyLoad 最后跑的」
2. 不再读父节点 `params`
3. 校区/学段变化变可观测（问题 2 解决）
4. 不再有受控组件的值错位（问题 1 解决）

## 4. 范围约束

- 只改 `src/pages/course/components/CreateCourseDialog.vue`
- 教材章节、核心教案、授课工具、列表页、其它页面一律不动
- 不新增纯逻辑函数；`course-basic-data.ts` 的 `resolveGradeEntities` / `findGradeByGradeId` 保持不变
- 纯逻辑模块本轮无新增单测需求（`resolveGradeEntities` 已有 4 例覆盖）

## 5. 需在 spec 中澄清的既有设计冲突

- `defLoading` 原职责之一是「回显期防止 watch 触发重置」。watch 删除后该职责消失，
  但 `defLoading` 仍用于表单 loading 态，**保留**（并继续阻止回显期间的用户交互）。
- `GRADE_RESET_FIELDS.chapters` 是模块级共享数组（`as const` 对象里的同一引用），
  每次 `Object.assign` 都把同一数组引用赋给 `form.chapters`。属既有隐患，
  本轮改为每次新建数组，一并修掉。
