# 学科/班级不随年级重新查询 · 原始需求

**日期：** 2026-09-30（v2 交付后的联调反馈）
**上游需求：** [01-原始需求.md](./01-原始需求.md) · [02-自检修复与提交三id.md](./02-自检修复与提交三id.md)
**上游 spec：** [../specs/01-dev-spec.md](../specs/01-dev-spec.md)

## 1. 用户反馈（联调实测）

> 「逻辑有问题，我选完了年级后，没有重新根据我选的年级去查学科和班级」

补充观察（用户实测）：

> 「有时候发了请求，有时候请求没发」

> 学科接口 `schoolGradeSubjectsList` 的响应字段是 **`name`** 和 **`id`**

## 2. 缺陷 A：重置 watch 的 `prev === undefined` 守卫导致首次选择被吞（间歇性）

### 2.1 现象

`schoolGradeSubjectsList` / `schoolClassList` **有时发请求、有时不发**，取决于是否有上次创建记录。

### 2.2 根因

v2 的重置 watch 首行：

```ts
async (next, prev) => {
  if (prev === undefined || next === prev) return
  ...
}
```

Vue 的 `watch`（未加 `immediate`）**首次触发时 `prev` 恒为 `undefined`**，
因此该 watch 的第一次触发必然被这行早退。是否发生，取决于此前是否已有代码触发过它：

| 场景 | create 模式回显 | 用户第一次选年级 | 结果 |
|------|----------------|----------------|------|
| 有上次记录、回显成功 | 回显时 watch 首次触发 → 被 `prev===undefined` 吞掉 | `prev` 已有值 | 发请求 ✓ |
| 无上次记录，或回显走 §9.2 边界分支（未写 `ref*`） | watch 从未触发 | 首次触发即被吞 | **不发请求** ✗ |
| 同上，再选一次年级 | — | `prev` 已有值 | 发请求 ✓ |

### 2.3 为什么不能直接删这行（承重作用）

该守卫原本用于**阻止 create 模式回显触发重置**。但 create 模式
（`loadFormCache`）**从未设置 `defLoading`** —— `defLoading.value = true` 只出现在
编辑模式分支（`CreateCourseDialog.vue:539`），create 分支（约 `:627`）直接
`await loadFormCache()`。若直接删除守卫，create 模式回显会误触发「清空 + 重载」。

## 3. 缺陷 B：学科响应字段名取错，教材 `baseCourseId` 恒空

v2 按 `item.subjectName ?? item.name` 取显示名、`item.baseSubjectId` 取基础学科 id。
用户实测响应字段为 **`name`** 与 **`id`**：

- 显示名：`item.subjectName` 不存在 → 靠 `?? item.name` 兜住，**侥幸正确**
- 基础学科 id：`item.baseSubjectId` **不存在** → `undefined`
  → `selectedBaseSubjectId()` 返回 `''`
  → `buildTextbookQuery({ baseCourseId: '' })` 返回 `null`
  → **教材版本下拉始终为空**（用户在联调中尚未触达该步骤）

> 这与第一轮 requirements 中「取学科列表中的 `baseSubjectId` 字段」的原始描述不符，
> 以用户实测的 `id` 为准。

## 4. 修法（P1 决策：两步都做）

### 4.1 缺陷 A

1. **先补** create 模式回显的 `defLoading` 保护，使其与编辑模式一致
2. **再删** `prev === undefined` 守卫，改为只判 `next === prev`

顺序不可颠倒：先补保护再删守卫，否则会出现「回显误触发重置」的中间态。

### 4.2 缺陷 B

`item.baseSubjectId` → `item.id`；显示名固定用 `item.name`（去掉多余的 `subjectName` 兜底，
避免掩盖字段名再次变更的问题）。

## 5. 范围约束

- 只改 `src/pages/course/components/CreateCourseDialog.vue`
- 教材章节、核心教案、授课工具、列表页、其它页面一律不动
- 不新增纯逻辑函数、不新增单测（本次为事件守卫与字段名修正，无可抽离的纯逻辑）

## 6. 遗留待确认

缺陷 A 修完后，「学科下拉空白」若仍出现，则问题落在缺陷 B 的响应结构上
（例如响应是 `{list: [...]}` 而非数组）。届时需用户提供实际响应结构。
