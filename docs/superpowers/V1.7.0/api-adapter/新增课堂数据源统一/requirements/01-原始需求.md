# 新增课堂数据源统一 · 原始需求

## 1. 背景

课堂管理列表页（`/classroom-app/course/course-management/course-list`）的「新增课堂」弹窗中，
年级、学科、班级三项的数据来源分散、彼此无关联性，需要统一为学校实体数据源。

现状（`src/pages/course/components/CreateCourseDialog.vue`）：

| 字段 | 现状来源 | 所属域 |
|------|---------|--------|
| 年级 `analysisGradeName` | `GET /analysis/dict/item-list?dictCode=grade`（平铺 ElSelect） | analysis 域全局字典 |
| 学科 `subjectName` | `GET /backstage/dict/item-list?dictCode=teachingClassroomSubjectName`（平铺 ElSelect） | backstage 域全局字典 |
| 班级 `refClassSnapshotPrimaryId` | 5 级懒加载级联：校区 → 学段 → 学年 → 年级 → 班级 | backstage 域学校实体 |
| 教材版本 `textbookEdition` | `gradeToNumber(年级名)` + `gradeToPhase(年级名)` + `GET /qbank/courses/grouped` 反查 `courseId` → `GET /qbank/textbooks/list` | qbank 域 |
| 教材章节 `chapters` | `GET /qbank/chapters/tree/{textbookId}` | qbank 域 |

问题：年级与班级对「年级」有两套互不相通的定义；教材版本的入参完全靠前端解析年级中文字符串
（`gradeToNumber`）猜出 `gradeLevelCode`，且学科需与 qbank 的 `courseCodeName` 字面相等才能反查
`courseId`；解析失败时静默返回空列表，页面无任何提示。

## 2. 需求原文

### 改动 1：年级改为三级级联懒加载

年级选择方式由平铺下拉改为懒加载级联，三级：**校区 + 学段 + 年级**，
形态参照弹窗内已有的「上课班级」级联。

- 校区：`/api/backstage/school/schoolCampusList`
  ```json
  { "schoolId": "1920062619731116034", "state": 1 }
  ```
  （`state`：1 启用、2 禁用）
- 学段（按所选校区查询）：`/api/backstage/schoolConfig/schoolStageList`
  ```json
  { "schoolId": "1920062619731116034", "campusId": "1920062619760476162" }
  ```
- 年级（按所选学段查询）：`/api/backstage/schoolConfig/currentGradeList`
  ```json
  { "schoolId": "1920062619731116034", "campusId": "1920062619760476162",
    "stageId": "1920064906671177730", "yearId": "1898938382593343489" }
  ```

- 学年（`currentGradeList` 所需 `yearId` 的来源）：`/api/backstage/schoolConfig/currentYear`
  ```json
  { "schoolId": "1920062619731116034" }
  ```
  取响应中的 `id` 作为 `yearId`。入参只依赖 `schoolId`，不依赖校区或学段。

### 改动 2：学科

保持原下拉形态，接口改为 `/api/backstage/schoolConfig/schoolGradeSubjectsList`：

```json
{ "baseGradeId": "1898938050664513538", "stageId": "1920064906671177730" }
```

> 注意：取年级列表中的 `baseGradeId`，**而非**年级列表条目的 `id`。

### 改动 3：班级

保持原模式，接口为 `/api/backstage/schoolClass/schoolClassList`：

```json
{ "schoolId": "1920062619731116034", "campusId": "1920062619760476162",
  "stageId": "1920064906671177730", "gradeId": "2087810071933476866" }
```

> 新入参不含 `yearId`、不含 `classType`（原实现含）。

### 改动 4：教材版本

接口与原来一致，仅调整入参：

| 参数 | 必填 | 说明 | 取值来源 |
|------|------|------|---------|
| `baseCourseId` | 是 | 基础学科 ID | 学科列表条目的 `baseSubjectId` |
| `baseEducationStageCode` | 是 | 学段：`primary` 小学 / `middle` 初中 / `high` 高中 | 学段列表条目的 `type` |
| `gradeLevelCode` | 否 | 年级码 1~12（从小学一年级开始） | 年级列表条目的 `number` |

### 改动 5：教材章节

与原来保持一致，不变。

### 改动 6：重置联动

**只要切换了年级，学科、班级、教材版本、关联章节这 4 者都要重置。**

## 3. 范围约束

- 弹窗原有业务逻辑（核心教案上传/平台选取、授课工具开关、教案编辑锁、提交校验、
  `normalizeCourseSubmitForm` 核心教案字段扁平化）**保持不变**，本次只改数据源。
- 教材章节接口与 `transformChapters` 不变。

## 4. P1 决策记录（2026-09-30，用户确认）

| 议题 | 决策 |
|------|------|
| `analysisGradeName` / `subjectName` 提交值 | **存名称**：`analysisGradeName` 存 `grade.name`、`subjectName` 存学科名；后端字段口径不变，历史课堂编辑回显不破 |
| 班级控件形态 | **换成 `ElSelect`**：选完年级后一次性拉全量班级平铺显示 |
| 级联回显 | 后端已在 `getById` / `getLatestRecord` 返回 `campusId`、`stageId`、`gradeId`，前端按 ID 逐级回显 |

### P1 决策的连带影响（已在 spec 中落定）

1. 年级级联的 v-model 存 `gradeId`（级联控件需要），`analysisGradeName` 在年级 change 时
   从选中节点 label 同步写入（提交用）。表单拆为两个值。
2. `gradeLevelCode` 与 `baseEducationStageCode` 直接取自级联选中节点的 `number` / `type`，
   发生在提交之前，**不再需要** `gradeToNumber` / `gradeToPhase` 解析年级名。
3. 班级改 `ElSelect` 后，`setOptsForm` 中依靠
   `classTreeSelect.getCheckedNodes(true)[0].data.label` 取 `className` 的逻辑需改为
   按班级 id 在选项数组中查 label。
