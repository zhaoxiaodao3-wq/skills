# 切回旧学段后学科不请求 · 原始需求

**日期：** 2026-09-30（v4 交付后的联调反馈，第 3 轮）
**上游需求：** [04-年级级联改用完整路径.md](./04-年级级联改用完整路径.md)
**上游 spec:** [../specs/01-dev-spec.md](../specs/01-dev-spec.md)

## 1. 用户反馈（精确复现路径）

> 「问题路径复现了，就是当我选择了一个完整的路径查到了具体的年级，这时候去切换了一个学段选择了别的年级，然后这时候重新去选择那些选过的年级，就不请求了」

关键确认：

> 「班级能正常出，只有学科空」

## 2. 根因

`gradeInfoMap` / `stageInfoMap` 在 `handleGradeLoadNode` 每次加载时**整体覆盖**：

```ts
gradeInfoMap.value = gMap     // ← 覆盖，不是合并
```

而 Element Plus 的懒加载级联会**缓存已加载节点的子节点**：
某个学段一旦展开过（level 2 执行过），再切回该学段时 **lazyLoad 不会再次执行**。

于是：

| 步骤 | 发生了什么 | `gradeInfoMap` | `loadSubjectOptions` |
|------|-----------|----------------|---------------------|
| 1. 选 C1/S1/G1 | level 2 执行，S1 的年级入表 | `{S1年级}` | `baseGradeId` 命中 → 发请求 ✓ |
| 2. 切到 S2 选 G2 | level 2 执行，**覆盖掉 S1** | `{S2年级}` | 命中 G2 → 发请求 ✓ |
| 3. **回 S1 再选 G1** | **level 2 不再执行**（子节点已缓存） | 仍是 `{S2年级}` | `gradeInfoMap[G1]` = undefined → `baseGradeId` = `''` → **第一行 return，不发请求** ✗ |

`loadSubjectOptions` 的早退：

```ts
if (!baseGradeId || !stageId) { subjectOptions.value = []; return }
```

**班级不受影响**——`loadClassOptions` 的入参（`campusId` / `stageId` / `gradeId`）
全部来自级联 path，不查映射表。这与用户实测「班级能正常出，只有学科空」完全一致。

## 3. 修法（P1 决策）

### 3.1 合并而非覆盖

| 位置 | 现状 | 改法 |
|------|------|------|
| level 1（学段） | `stageInfoMap.value = sMap` | `stageInfoMap.value = { ...stageInfoMap.value, ...sMap }` |
| level 2（年级） | `gradeInfoMap.value = gMap` | `gradeInfoMap.value = { ...gradeInfoMap.value, ...gMap }` |
| 回显 `loadGradeCascadeForEcho` | 整体赋值 | **保持整体赋值**（弹窗每次打开是全量重新初始化，无需合并） |

**同一校区内，各学段的年级是互斥分区**（一个年级只属于一个学段），因此合并不会撞 key。

### 3.2 跨校区清空

合并会带来一个副作用：切换校区后，新校区的 `gradeId` 若与旧校区重名，会读到旧数据。
故在 `handleGradeChange` 中检测校区变化并清空：

```ts
const prevCampusId = form.refCampusId
form.refCampusId = campusId
...
// 跨校区：年级 / 学段数据不可复用，清空后由 lazyLoad 重新填充
if (prevCampusId && prevCampusId !== campusId) {
  gradeInfoMap.value = {}
  stageInfoMap.value = {}
}
```

> `prevCampusId` 加了非空判断：首次进入（`prevCampusId === ''`）不清空，
> 否则会把 level 2 刚为当前校区填好的数据又抹掉。

### 3.3 时序自检

| 步骤 | path | `prevCampusId` → `campusId` | 是否清空 | 之后 level 2 |
|------|------|---------------------------|---------|--------------|
| 首次点校区 C1 | `['C1']` | `''` → `'C1'` | 否（prev 为空） | — |
| 点学段 S1 | `['C1','S1']` | `'C1'` → `'C1'` | 否 | 执行，合并 S1 年级 |
| 点年级 G1 | `['C1','S1','G1']` | `'C1'` → `'C1'` | 否 | — |
| 改点年级 G2 | `['C1','S1','G2']` | 同上 | 否 | — |
| **回 S1 选 G1** | `['C1','S1','G1']` | 同上 | 否 | **不再执行，但表里已有 G1** ✓ |
| 改点校区 C2 | `['C2']` | `'C1'` → `'C2'` | **是** | — |
| 点学段 S2 | `['C2','S2']` | `'C2'` → `'C2'` | 否 | 执行，合并 S2 年级 |
| 点年级 G2' | `['C2','S2','G2']` | 同上 | 否 | — |

关键点：**清空只发生在"点校区"这一步**，而 level 2 的填充发生在其后（展开学段时），
两者不冲突。

## 5. 浏览器复现尝试的记录

用户建议用浏览器复现。实际尝试结果：**内置 Browser 为独立会话，无登录态**——
打开目标页后停在 loading，Network 中 **xhr/fetch 为 0 条**（连鉴权请求都未发出），
无法进入业务页面。因此本轮根因由**代码走查 + 用户精确复现路径**交叉确认，
而非浏览器实测。

后续若需浏览器复现，需用户在右侧 FilePanel Browser 中自行登录后接管。
