# 教学小组翻页排序失效 · 原始需求

**版本：** V1.4.9
**分类：** fix
**关联组件：** `src/pages/school/teacher-portrait/components/teaching-group/`
**关联历史模块：** `docs/superpowers/v1.4.8/feature/教学小组默认排序与选中/`

## 问题描述

教师画像页「教学小组」组件：首次进入时小组列表按人数降序排序正常，但**切换分页后排序失效**，新页数据按接口原始顺序展示；翻回第 1 页后排序同样失效。

## 用户诉求

- 翻页后排序不能失效，任何一页都必须按人数降序展示
- 逻辑必须闭环：不允许存在能绕过排序的状态路径

## 根因分析

`TeachingGroupContainer.vue` 的 `loadGroups()` 中排序被条件守卫：

```ts
if (
  !selectedGroupId.value
  && (view.value === 'groups' || view.value === 'groups-empty')
) {
  groups.value = sortTeachingGroupsByMemberCountDesc(groups.value)
}
```

而 v1.4.8「教学小组默认排序与选中」引入的两条规则使该条件在翻页时**永远不成立**：

1. 组件挂载后 `tryInitialAutoSelect()` 会设置 `selectedGroupId`（3.2 初始化选中）
2. 选中一旦建立，翻页 / 切换小组均**不清空**（3.3 选中保持）

因此首次加载之后 `selectedGroupId` 恒为非空 → 翻页触发的 `loadGroups()` 恒跳过排序。

v1.4.8 spec 存在内部矛盾：3.1「未选中小组时才排序」、3.4「翻页 → 重新 loadGroups + 排序」、3.3「选中永不清空」三者互斥，实现按 3.1 落地导致 3.4 失效。

## 验收要点

- [ ] 任意小组分页（含翻回第 1 页）均按 `memberCount` 降序展示
- [ ] 相同人数的小组相对顺序随机（沿用 v1.4.8 规则）
- [ ] 翻页不触发自动选中（沿用 v1.4.8 规则）
- [ ] 已选中成员 / 小组高亮在翻页后保持（沿用 v1.4.8 规则）
- [ ] 排序逻辑闭环：不存在依赖 UI 选中态的排序分支
