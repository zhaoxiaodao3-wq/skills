# Superpowers Harness 门禁体系 — 原始需求

## 背景

项目已具备 `superpowers-demand-workflow` 技能，规范 Superpowers 文档输出路径（requirements → specs → plans 四层目录）。但在实际 AI 辅助开发中仍存在以下问题：

1. **Agent 跳过流程（最优先）**：直接修改 `src/` 代码，不建需求目录、不写 spec/plan
2. **文档写错位置**：新文档落入旧扁平路径 `docs/superpowers/specs/` 等
3. **产出质量不稳**：spec/plan 不完整、开发偏离规格
4. **新项目迁移成本高**：每次手动配置规则、技能、脚本

用户希望结合 Harness Engineering 方法论，在现有 Superpowers 流程之上构建适合本项目的 Harness 体系，并打包为可快速迁移到其他项目的 skill。

## 目标

- 在 **不替代** `superpowers-demand-workflow` 的前提下，叠加 Harness 层（门禁 + 校验 + 迁移）
- 分三期实施，第一期主攻「防跳过流程」
- 第一期采用 **宽松模式**：违规警告、不阻断 commit
- 最终可通过 bootstrap 一键安装到其他项目

## 约束

- 保留现有 `SUPERPOWERS_RULES.md` 与四层目录规范
- 不破坏现有 181+ 份 superpowers 存量文档
- `.agents/skills/` 为技能单一真相源，bootstrap 同步到 `.cursor/skills/`
- 技能描述与文档正文使用简体中文
