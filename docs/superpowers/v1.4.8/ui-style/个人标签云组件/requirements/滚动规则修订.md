## 三、规则变更

### 修订前（v1，已废弃）

- 默认可视区域固定展示 4 个模块（话语特色、情感风格、权力关系、1 个学科适配）
- 总模块数量超过 4 个时，模块容器支持上下滚动

### 修订后（本次生效）

- 当存在**多个学科适配模块**，且模块列表总高度**超过容器高度**时，模块容器支持**上下滚动**查看全部模块
- 滚动交互样式对齐设计稿
- 组件标题「个人标签云」固定，不随模块列表滚动

### 补充说明

- 是否出现滚动条以**实际渲染高度**为准，与模块个数无硬性对应关系
- 内容未超出容器高度时，不应出现多余滚动条
- 多模块滚动交互需流畅无卡顿，滚动条样式、滚动范围严格对齐设计稿规范

## 四、Mock 验证场景

| 场景 | 说明 | 预期 |
|------|------|------|
| 单学科 | 话语 + 情感 + 权力 + 1 个学科 | 视口足够高时无滚动条 |
| 多学科 | 话语 + 情感 + 权力 + 3 个及以上学科 | 超出容器高度时可上下滚动 |
| 缺省 | 未选教师或数据缺失 | 4 模块全零，通常无需滚动 |

## 五、验收要求

1. 模块总高度超出侧栏容器时，仅模块列表区域纵向滚动
2. 可滚动查看全部学科适配模块
3. 滚动条样式对齐 Figma 细滚动条规范
4. 不修改既有条形列表展示形式
