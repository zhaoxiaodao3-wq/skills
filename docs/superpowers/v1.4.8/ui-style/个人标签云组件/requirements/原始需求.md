
# 个人标签云组件开发需求文档

## 一、需求概述
本次提供的2份Figma设计稿链接暂无法直接解析内容，以下需求基于业务逻辑描述整理，所有视觉样式、标签布局、交互细节均以对应设计稿节点为准。组件用于可视化展示教师个人教学特征标签，覆盖话语特色、情感风格、权力关系、学科适配四大维度，基于ECharts实现标签云效果，支持多学科适配模块扩展与滚动查看，遵循项目统一的工程化、组件化开发规范，保障可复用性与可扩展性。

## 三、组件状态定义
### 1. 完整数据状态
为组件正常展示态，当标签相关数据可正常获取时渲染，完整展示所有维度模块、标签云、分类标题等全部内容。
### 2. 缺省状态
当核心数据缺失、接口异常无法获取标签数据时，切换展示缺省状态，视觉样式严格对齐缺省设计稿实现，不得自定义缺省样式。

## 四、核心模块与标签规则
组件共包含4类标签维度模块：话语特色、情感风格、权力关系、学科适配。其中学科适配维度支持多学科并存，每个学科独立为一个模块。

### 1. 标签枚举与等级规则

### 2. 通用展示与排序规则
- **固定展示规则**：每个模块内的所有枚举标签必须完整展示，即使对应标签的统计数量为0也不得隐藏，标签数量为固定值。
- **模块内标签排序规则**：单个模块内的标签按以下优先级排序：
  1.  第一优先级：按标签对应的统计数量从多到少排列；
  2.  第二优先级：数量相等时，按标签等级从高到低排列（等级顺序以上述枚举序号为准，序号越小等级越高）。

### 3. 学科适配模块扩展规则
- 学科适配维度对应具体学科（如数学、语文等），支持同时存在多个学科的适配标签模块，每个学科独立为一个完整模块，模块内标签规则遵循通用规则。
- 模块标题展示对应学科名称，需与学科适配标签做明确区分。

### 4. 模块布局与滚动规则

> 滚动规则已于 2026-07-06 独立修订，详见 [滚动规则修订.md](./滚动规则修订.md)。

- 当存在多个学科适配模块，如果高度超过了容器高度，模块容器支持**上下滚动**查看全部模块，滚动交互样式对齐设计稿。

## 五、图表实现规范
1.  遵循项目统一技术规范，组件内所有标签云效果**统一使用 ECharts** 进行实现，不得引入其他图表库。
2.  标签的字号大小、配色方案、间距、字体样式、hover效果等所有视觉细节，严格对齐设计稿效果。
3.  标签云需支持响应式自适应，随模块容器尺寸变化自动调整标签布局，无溢出、错位、重叠等异常。
4.  多模块滚动交互需流畅无卡顿，滚动条样式、滚动范围严格对齐设计稿规范。

## 六、UI与开发通用规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件，可基于现有组件进行二次样式定制与功能封装，在严格对齐设计稿效果的前提下，最大化复用组件库能力。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。样式隔离方案遵循项目现有工程规范。
3.  **响应式适配**：组件需具备完整的响应式适配能力，兼容项目覆盖的主流屏幕尺寸与分辨率，不同视口下布局合理、内容完整展示，无溢出、错位、遮挡、文字截断等视觉异常。
4.  **架构设计**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理的扩展插槽、配置项与钩子，支持后续标签新增、维度调整与功能迭代；所有文件目录划分遵循项目现有前端工程规范，本需求不做强制指定。

## 七、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 全量正常数据场景：所有标签均有统计数量，验证排序规则与完整展示效果；
    - 零值标签场景：部分标签数量为0，验证固定展示规则；
    - 同数量标签场景：多个标签数量相等，验证等级排序逻辑；
    - 单学科适配场景：仅 1 个学科适配模块，视口足够高时无滚动；
    - 多学科适配场景：3 个及以上学科适配模块，超出容器高度时验证上下滚动交互（详见 [滚动规则修订.md](./滚动规则修订.md)）；
    - 缺省状态场景；
    - 边界场景：所有标签数量均为0的极端场景。

## 八、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与标签样式细节，全标签完整还原，保证1:1还原效果；
2.  标签枚举、排序规则、多模块滚动逻辑准确无误，覆盖所有边界分支，无逻辑异常；
3.  标签云统一使用ECharts实现，样式与交互符合设计稿要求，支持响应式自适应；
4.  兼容接口异常、字段缺失、数据格式异常等边界场景，缺省状态展示符合设计稿规范；
5.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
6.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
7.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
