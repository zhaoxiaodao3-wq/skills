# 教师列表组件开发需求文档

## 一、需求概述
本次提供的2份Figma设计稿链接暂无法直接解析内容，以下需求基于业务逻辑描述整理，视觉还原需严格以对应设计稿节点为准。组件需遵循项目统一的工程化、组件化开发规范，实现列表展示、分页、搜索重置等核心能力，兼顾可复用性与响应式适配。

## 二、设计稿资源
所属项目：明餐开发稿 · 团队星版

## 三、权限控制规则
1.  组件可见性受用户角色控制：仅身份为**校级管理员**或**管理员**的用户可展示本组件；非上述角色用户不渲染组件。
2.  权限判断逻辑复用项目现有用户角色工具能力，遵循项目统一的权限校验规范。

## 四、组件状态定义
### 1. 初始化列表态
- 为组件默认初始状态，展示教师列表全量数据（无搜索筛选条件）。
- 设计稿内所有列表字段、标签、辅助信息等均需完整还原，未明确特殊处理规则的字段，均按接口返回原值直接展示。

### 2. 无成员空状态
- 触发条件：列表无任何教师成员数据时展示。
- 视觉样式严格对齐空状态设计稿实现，不得自定义空态样式。

## 五、分页规则
1.  教师列表采用分页展示，默认每页展示 **10条** 数据。
2.  分页组件优先复用 Element Plus 原生分页组件，样式按设计稿要求二次定制。

## 六、搜索与重置交互逻辑
### 1. 搜索触发方式
支持两种搜索触发方式，执行效果完全一致：
- 点击搜索输入框旁的搜索图标；
- 搜索输入框处于聚焦状态时，按下回车键。

### 2. 空关键词搜索规则
若搜索输入框无内容时触发搜索，则直接重置列表为初始化状态，加载第一页全量数据，清除所有搜索筛选条件。

### 3. 重置按钮规则
点击重置按钮后，列表直接恢复至初始化状态：
- 搜索输入框清空内容；
- 分页重置为第一页；
- 加载全量初始数据，清除所有筛选条件。

## 七、UI与开发规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件（列表、分页、输入框、按钮等），避免重复开发基础控件；可基于现有组件进行二次样式定制，严格对齐设计稿视觉效果。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。
3.  **响应式适配**：组件需具备响应式适配能力，兼容项目覆盖的主流屏幕尺寸，不同视口下列表布局合理、内容完整展示，无溢出、错位、遮挡等视觉异常。
4.  **架构设计**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理扩展空间，支持后续字段新增、功能迭代，无需重构核心结构。所有文件的目录划分、存放路径均遵循项目现有前端工程规范。

## 八、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 列表多数据、单页/多页分页场景
    - 无成员空状态场景
    - 带关键词搜索、空关键词搜索场景
    - 重置按钮触发初始化场景

## 九、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与交互态，保证1:1还原效果；
2.  搜索、重置、分页等交互逻辑准确无误，状态切换清晰，无逻辑异常；
3.  兼容接口异常、数据为空等边界场景，空状态展示符合设计稿规范；
4.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
5.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
6.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
