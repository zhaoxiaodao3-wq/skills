# 教师画像组件开发需求文档

## 一、需求概述
本次提供的4份Figma设计稿链接暂无法直接解析内容，以下需求基于业务逻辑描述整理，所有视觉样式、交互细节均以对应设计稿节点为准。组件需基于教学风格数据完成教师画像可视化展示，包含用户画像图、业务指标、个人特征标签等核心模块，整体遵循项目统一的工程化、组件化开发规范，保障可复用性与可扩展性。

## 三、组件状态定义
### 1. 正常有数据状态
组件默认展示态，当画像核心数据可正常获取时渲染，完整展示用户画像图、全部业务指标、个人特征标签等模块内容。
### 2. 缺省状态
当核心数据缺失、接口异常无法获取画像数据时，切换展示缺省状态，视觉样式严格对齐缺省设计稿实现，不得自定义缺省样式。

## 四、用户画像图生成规则
1.  匹配维度：基于【教学风格与弹性特征】模块输出的**主导风格**、**辅助风格**，结合用户性别（男/女）三个维度，匹配对应画像图。
2.  组合总量：共支持20种风格+性别组合，对应20张高清头像资源。
3.  实现方式：复用项目现有头像映射方法，从OSS获取对应高清头像资源，无需本地存储图片资产。

## 五、类型标签样式与等级规则
1.  学科适配标签共分为五种类型，对应五种差异化视觉样式，严格对齐「类型标签五种样式」设计稿实现。
2.  标签适配等级由高到低对应关系如下：

| 综合得分区间 | 标签文案 | 适配等级 |
| :--- | :--- | :--- |
| 9-10分 | 高度适配 | 1级（最高） |
| 6-8分 | 中度适配 | 2级 |
| 3-5分 | 低度适配，需针对性调整 | 3级 |
| 0-2分 | 风格与学科特性存在明显偏差 | 4级（最低） |

## 六、数据字段展示规范
本章节仅列出存在特殊处理规则的字段；设计稿中出现的其余所有展示字段，均按设计稿标注的文案、格式、单位直接渲染，不做额外数据转换。

| 字段名称 | 展示处理规则 | 单位 |
| :--- | :--- | :--- |
| 上课时长 | 仅展示整数数值；若接口返回值包含小数，直接截断小数部分及后续内容，不做四舍五入处理 | 分钟 |

## 七、个人特征模块标签规则
个人特征模块包含话语特色、情感风格、权力关系、学科适配四个维度，标签选取与展示规则如下：

### 1. 标签选取规则
- **话语特色**：取该维度标签列表中排序第一的标签
- **情感风格**：取该维度标签列表中排序第一的标签
- **权力关系**：取该维度标签列表中排序第一的标签
- **学科适配**：按以下优先级规则选取最终展示标签
  1.  仅存在1个学科时：取该学科下排序第一的标签；
  2.  存在多个学科时：
      - 若存在与主学科匹配的学科项：取该主学科下排序第一的标签；
      - 若无主学科匹配项：取所有学科中出现数量最多的标签（相同标签不叠加计数）；
      - 若标签出现数量相同：取适配等级最高的标签，等级排序参考本第五节的等级由高到低规则。

### 2. 标签样式规则
- 个人特征模块内的多个标签，样式需按设计稿规范**交替展示**，对应不同的视觉样式版本。
- 标签样式库严格对齐「个人特征模块不同样式」设计稿，不得自定义样式。

## 八、UI与开发通用规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件，可基于现有组件进行二次样式定制与功能封装，在严格对齐设计稿效果的前提下，最大化复用组件库能力。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。样式隔离方案遵循项目现有工程规范。
3.  **响应式适配**：组件需具备完整的响应式适配能力，兼容项目覆盖的主流屏幕尺寸与分辨率，不同视口下布局合理、内容完整展示，无溢出、错位、遮挡、文字截断等视觉异常。
4.  **架构设计**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理的扩展插槽、配置项与钩子，支持后续字段新增、样式调整与功能迭代；所有文件目录划分遵循项目现有前端工程规范，本需求不做强制指定。

## 九、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 全量正常数据场景，覆盖不同性别、不同风格组合的画像图匹配验证
    - 缺省状态场景
    - 单学科、多学科、同数量不同等级等学科适配标签的边界场景
    - 多标签交替样式展示场景
    - 上课时长带小数的整数截断验证场景

## 十、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与样式细节，全字段完整还原，保证1:1还原效果；
2.  画像图匹配、标签选取逻辑准确无误，覆盖所有边界分支，无逻辑异常；
3.  兼容接口异常、字段缺失、数据格式异常等边界场景，缺省状态展示符合设计稿规范；
4.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
5.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
6.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
