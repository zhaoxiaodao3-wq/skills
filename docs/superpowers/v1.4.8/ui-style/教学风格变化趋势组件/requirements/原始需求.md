# 教学风格变化趋势组件开发需求文档

## 一、需求概述
本次提供的2份Figma设计稿链接暂无法直接解析内容，以下需求基于业务逻辑描述整理，所有视觉样式、图表细节均以对应设计稿节点为准。组件用于展示多报告周期下教师教学风格的变化趋势，基于ECharts实现可交互的趋势图表，遵循项目统一的工程化、组件化开发规范，保障可复用性与可扩展性。

## 三、组件状态定义
### 1. 完整数据状态
为组件正常展示态，当多期报告风格数据可正常获取时渲染，完整展示趋势图表、坐标轴、图例等全部内容。
### 2. 缺省状态
当核心数据缺失、接口异常无法获取趋势数据时，切换展示缺省状态，视觉样式严格对齐缺省设计稿实现，不得自定义缺省样式。

## 四、图表核心实现规则
组件内统计图表统一使用 ECharts 实现，不得引入其他图表库，具体坐标轴与交互规则如下：

### 1. 纵坐标轴规则
纵轴固定展示5类教学风格维度，顺序如下：
- 严厉规训型
- 权威传授型
- 激情讲授型
- 理性启发型
- 温暖引导型

坐标轴样式、标签排版、刻度规则严格对齐设计稿效果。

### 2. 横坐标轴规则
- 横轴为报告序列，按时间升序排列，时间越早的报告排列越靠左；
- 标签命名规则：
  1.  优先使用大写字母 A-Z，每个字母对应序号 1-99，标签格式为「字母+数字」（如 A1、A2…A99、B1、B2…B99）；
  2.  大写字母序列用尽后，接续使用小写字母 a-z，每个字母对应序号 1-99，标签格式为「字母+数字」（如 a1、a2…a99）；
- 单屏默认最多展示 26 个坐标点，超出部分通过交互操作查看。

### 3. 图表交互能力
基于 ECharts 原生能力实现以下交互效果：
- 滚轮缩放：支持通过鼠标滚轮调整横轴坐标范围，放大/缩小视图区间；
- 拖拽平移：支持按住图表横向拖拽，切换视图查看不同区间的报告数据。

## 五、UI与开发通用规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件，可基于现有组件进行二次样式定制与功能封装，在严格对齐设计稿效果的前提下，最大化复用组件库能力。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。样式隔离方案遵循项目现有工程规范。
3.  **响应式适配**：组件需具备完整的响应式适配能力，兼容项目覆盖的主流屏幕尺寸与分辨率，不同视口下图表容器自适应调整，内容完整展示，无溢出、错位、遮挡等视觉异常。
4.  **架构设计**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理的扩展插槽、配置项与钩子，支持后续字段新增、样式调整与功能迭代；所有文件目录划分遵循项目现有前端工程规范，本需求不做强制指定。

## 六、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 常规数据场景：26个以内坐标点，单屏完整展示
    - 超量数据场景：超过26个坐标点，验证滚轮缩放与拖拽平移交互
    - 极限边界场景：大写字母序列用尽，接续小写字母标签的场景
    - 缺省状态场景
    - 单维度数据缺失、数据格式异常等边界场景

## 七、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与图表样式细节，保证1:1还原效果；
2.  坐标轴命名规则、排序逻辑、交互能力实现准确无误，覆盖所有边界分支，无逻辑异常；
3.  兼容接口异常、字段缺失、数据格式异常等边界场景，缺省状态展示符合设计稿规范；
4.  图表统一使用ECharts实现，交互流畅无卡顿，支持响应式自适应；
5.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
6.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
7.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
