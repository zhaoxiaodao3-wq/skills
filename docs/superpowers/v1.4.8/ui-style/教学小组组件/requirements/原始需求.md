# 教学小组组件开发需求文档

## 一、需求说明
本次提供的3份Figma设计稿链接暂无法直接解析内容，以下需求基于业务逻辑描述整理，视觉还原需严格以对应设计稿节点为准。组件需遵循工程化、组件化设计原则，实现状态清晰、交互顺畅，同时兼容响应式适配。

## 三、权限控制规则
1.  组件可见性受用户角色控制：仅**小组管理员**身份的用户可展示本组件；非管理员用户不渲染组件。
2.  权限判断逻辑复用项目现有用户角色工具能力，遵循项目统一的权限校验规范。

## 四、组件状态与交互流程
组件包含三类核心状态，状态切换逻辑如下：

### 1. 小组列表态（默认初始状态）
- 展示内容：当前登录用户所管理的全部教学小组列表
- 交互规则：点击任意小组条目，即为选中该小组，同步切换至「成员列表态」

### 2. 成员列表态
- 触发条件：选中某一小组后进入
- 展示内容：当前选中小组内的所有成员列表
- 交互规则：点击任意成员条目，即为选中该成员，支持选中态视觉反馈
- 空态分支：若选中的小组内无任何成员，则切换展示「成员空状态」，不展示成员列表

### 3. 成员空状态
- 触发条件：已选中小组，但该小组下无成员数据时展示
- 视觉样式：严格对齐空状态设计稿实现，不得自定义空态样式

## 五、数据展示规则
1.  **全局空值规则**：组件内所有内容类展示字段，若对应数据无值、为空或接口返回异常时，统一展示占位符 `--`。
2.  列表字段完整还原：设计稿中出现的所有列表字段、标签、辅助信息、操作项等均需完整实现，未明确特殊规则的字段均按接口原值直接展示。

## 六、分页规则
1.  小组列表、成员列表均采用分页展示，默认每页展示 **10条** 数据。
2.  分页组件优先复用 Element Plus 原生分页组件，样式按设计稿要求二次定制。

## 七、UI与开发规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件（列表、分页、选中态等），避免重复开发基础控件；可基于现有组件进行二次样式定制，严格对齐设计稿视觉效果。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。
3.  **响应式适配**：组件需具备响应式适配能力，兼容项目覆盖的主流屏幕尺寸，不同视口下列表布局合理、内容完整展示，无溢出错位等异常。
4.  **架构与可扩展性**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理扩展空间，支持后续字段新增、功能迭代，无需重构核心结构。

## 八、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 小组列表多数据、单页/多页分页场景
    - 成员列表多数据、单页/多页分页场景
    - 小组内无成员的空状态场景
    - 单字段无值展示 `--` 的边界场景

## 九、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与交互态，保证1:1还原效果；
2.  状态切换逻辑清晰，选中态、空态、分页等交互符合规则，无逻辑异常；
3.  所有字段空值统一展示 `--`，兼容接口异常、字段缺失等边界场景；
4.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
5.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
6.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
