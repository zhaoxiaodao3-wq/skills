# 课堂结构清晰度组件开发需求文档

## 一、需求概述
本次提供的3份Figma设计稿链接暂无法直接解析内容，以下需求基于业务逻辑描述整理，所有视觉样式、图表细节均以对应设计稿节点为准。组件用于统计多份报告下课堂结构各维度的平均得分与综合等级，包含维度统计图表、总分等级标签、特征描述等核心内容，遵循项目统一的工程化、组件化开发规范，保障可复用性与可扩展性。

## 三、组件状态定义
### 1. 完整数据状态
为组件正常展示态，当多份报告的课堂结构数据可正常获取时渲染，完整展示维度得分图表、总分等级标签、特征描述等全部模块内容。
### 2. 缺省状态
当核心数据缺失、接口异常无法获取课堂结构数据时，切换展示缺省状态，视觉样式严格对齐缺省设计稿实现，不得自定义缺省样式。

## 四、数据计算与等级规则
### 1. 维度得分展示规则
- 共包含4个评估维度：目标清晰度、环节清晰度、逻辑清晰度、总结清晰度。
- 维度得分统计规则：基于多份报告数据，计算每个维度的平均分；平均分统一保留正整数展示，小数部分直接截断，不做四舍五入处理；每个维度同步展示对应的满分值。
- 所有维度数据通过图表可视化呈现，图表统一使用 ECharts 实现。

### 2. 总分等级映射规则
- 总分计算：4个维度的得分相加，得到课堂结构清晰度总得分。
- 根据总分匹配对应等级、特征描述与标签样式，各等级对应关系如下：

| 分数区间 | 等级 | 特征描述 |
| :--- | :--- | :--- |
| 85-100分 | 卓越 | 结构清晰，学生能清楚把握课堂脉络 |
| 70-84分 | 良好 | 结构较清晰，偶有模糊之处 |
| 55-69分 | 中等 | 部分环节不够清晰 |
| 40-54分 | 较弱 | 结构模糊，学生难以跟上 |
| 0-39分 | 薄弱 | 结构混乱，无清晰框架 |

- 每个等级对应独立的标签视觉样式，严格对齐「等级标签样式」设计稿实现，不得自定义样式。

## 五、图表实现规范
1.  遵循项目统一技术规范，组件内所有统计图表模块**统一使用 ECharts** 进行实现，不得引入其他图表库。
2.  图表的配色、维度标签、刻度、满分标识、提示框等所有视觉细节，严格对齐设计稿效果。
3.  图表需支持响应式自适应，随容器尺寸变化自动调整，保证不同屏幕下展示完整、无溢出错位。

## 六、UI与开发通用规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件，可基于现有组件进行二次样式定制与功能封装，在严格对齐设计稿效果的前提下，最大化复用组件库能力。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。样式隔离方案遵循项目现有工程规范。
3.  **响应式适配**：组件需具备完整的响应式适配能力，兼容项目覆盖的主流屏幕尺寸与分辨率，不同视口下布局合理、内容完整展示，无溢出、错位、遮挡、文字截断等视觉异常。
4.  **架构设计**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理的扩展插槽、配置项与钩子，支持后续字段新增、样式调整与功能迭代；所有文件目录划分遵循项目现有前端工程规范，本需求不做强制指定。

## 七、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 全量正常数据场景，覆盖所有维度得分、总分与等级完整展示
    - 缺省状态场景
    - 5个等级档位的边界分数场景（如85分、84分、70分、69分等），验证等级匹配逻辑
    - 平均分含小数的正整数截断验证场景
    - 单维度数据缺失等边界场景

## 八、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与样式细节，全字段完整还原，保证1:1还原效果；
2.  得分计算、等级匹配逻辑准确无误，覆盖所有分数区间边界，无等级错配、计算偏差；
3.  图表统一使用ECharts实现，样式与交互符合设计稿要求，支持响应式自适应；
4.  兼容接口异常、字段缺失、数据格式异常等边界场景，缺省状态展示符合设计稿规范；
5.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
6.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
7.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
