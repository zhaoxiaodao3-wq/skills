## 三、组件状态定义
### 1. 完整数据状态
为组件正常展示态，当教学风格相关数据可正常获取时渲染，完整展示风格类型、教学情境标签、弹性稳定性等全部模块内容。
### 2. 缺省状态
当核心数据缺失、接口异常无法获取风格数据时，切换展示缺省状态，视觉样式严格对齐缺省设计稿实现，不得自定义缺省样式。

## 四、核心模块业务规则
### 1. 教学情境模块
模块共覆盖5类教学场景，每类场景均分为强、中、弱三个等级，不同等级对应固定的标签文案，标签样式随等级差异化展示。

| 教学情境 | 强等级文案 | 中等级文案 | 弱等级文案 |
| :--- | :--- | :--- | :--- |
| 导入新知时 | 引人入胜 | 偶有亮点 | 有待提高 |
| 讲授核心概念时 | 条理清晰 | 偶有亮点 | 有待提高 |
| 学生回答错误时 | 耐心引导 | 偶尔引导 | 有待提高 |
| 课堂气氛低落时 | 善于活跃 | 偶尔活跃 | 有待提高 |
| 总结扩展时 | 回顾重点 | 偶尔总结 | 有待提高 |

- 标签视觉样式按强、中、弱分为三种，严格对齐「教学情境等级标签样式」设计稿实现，不得自定义样式。
- 需根据接口返回的各情境等级，自动匹配对应文案与对应样式的标签。

### 2. 教学风格类型模块
- 共包含5种教学风格类型：温暖引导型、理性启发型、激情讲授型、权威传授型、严厉规训型。
- 每种类型对应独立的选中态视觉样式，严格对齐「教学风格类型选中态样式」设计稿实现，选中态差异化展示。
- 主导风格对应选中态样式，辅助风格按设计稿规则展示。

### 3. 课中教学风格弹性模块
- 模块结构为「稳定性类型 + 固定描述文案」，共分为高、中、低三种稳定性等级，每种等级对应固定的描述文案，不可自定义修改。

| 稳定性等级 | 固定描述文案 |
| :--- | :--- |
| 高稳定性 | 每次上课表现高度一致，优势短板都很固定，风格稳定可预测。 |
| 中等稳定性 | 整体表现稳定，但有一个情境时好时坏，不太稳定。 |
| 低稳定性 | 多个情境表现飘忽不定，还没形成稳定的教学风格。 |

- 三种稳定性等级分别对应不同的模块视觉样式，严格对齐「教学风格弹性模块样式」设计稿实现。

## 五、UI与开发通用规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件，可基于现有组件进行二次样式定制与功能封装，在严格对齐设计稿效果的前提下，最大化复用组件库能力。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。样式隔离方案遵循项目现有工程规范。
3.  **图表规范**：遵循项目统一技术规范，组件内若包含统计图表，统一使用 ECharts 实现，不得引入其他图表库。
4.  **响应式适配**：组件需具备完整的响应式适配能力，兼容项目覆盖的主流屏幕尺寸与分辨率，不同视口下布局合理、内容完整展示，无溢出、错位、遮挡、文字截断等视觉异常。
5.  **架构设计**：采用业务逻辑与视图分离的架构设计，结构清晰、职责单一，预留合理的扩展插槽、配置项与钩子，支持后续字段新增、样式调整与功能迭代；所有文件目录划分遵循项目现有前端工程规范，本需求不做强制指定。

## 六、Mock数据方案
开发阶段先行使用Mock数据联调，不依赖真实后端接口，接口就绪后可无缝切换。
1.  Mock数据与业务代码、视图逻辑分离，存放方式遵循项目现有Mock管理规范。
2.  需覆盖以下场景：
    - 全量正常数据场景，覆盖所有模块完整展示
    - 缺省状态场景
    - 5类教学情境不同等级的组合场景
    - 5种教学风格类型分别选中的场景
    - 3种稳定性等级的切换场景
    - 单模块数据缺失等边界场景

## 七、开发要求
1.  视觉还原严格对齐Figma设计稿的尺寸、色值、间距、字体与样式细节，全字段完整还原，保证1:1还原效果；
2.  各模块文案映射、等级匹配逻辑准确无误，覆盖所有分支场景，无文案与样式错配；
3.  兼容接口异常、字段缺失、数据格式异常等边界场景，缺省状态展示符合设计稿规范；
4.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
5.  完成多屏幕响应式适配验证，覆盖项目主流分辨率；
6.  组件设计遵循工程化、组件化规范，具备可扩展性，便于后续迭代维护。
7. 图表统一使用ECharts实现，样式与交互符合设计稿要求，支持响应式自适应.
