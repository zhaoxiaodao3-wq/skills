# 教师数据统计组件开发需求文档
## 一、需求背景
本需求为前端组件开发任务，需基于指定Figma设计稿完成全字段1:1视觉还原，同时落地权限控制、数据处理、缺省兼容等业务逻辑。开发阶段先行使用Mock数据联调，整体采用业务逻辑与视图分离的架构设计，以工程化、组件化、可延展为核心目标，兼顾多屏幕响应式适配能力，保障组件的可复用性与可维护性。开发过程可通过 figma-mcp 工具辅助还原设计稿，所有文件的目录划分、存放路径均遵循项目现有前端工程规范与团队约定，本需求不做强制指定。

## 二、设计稿资源
设计稿所属项目：明餐开发稿 · 团队星版
共提供2份设计稿，分别对应「正常有数据状态」与「字段缺省状态」，开发需覆盖两种视觉样式下的全部展示字段：

2.  缺省状态设计稿：https://www.figma.com/design/vmbLwcwclGPoT3fWJWv7de/%E6%98%8E%E7%9D%BF%E5%BC%80%E5%8F%91%E7%A8%BF-%C2%B7%E5%9B%A2%E9%98%9F%E7%89%88?node-id=6696-20198&m=dev

## 三、权限控制规则
1.  组件可见性受用户岗位权限控制：仅当用户岗位为【普通教师】时，渲染展示本组件；非该岗位用户不渲染组件。
2.  角色权限判断逻辑复用项目现有工具能力，参考实现：`src\utils\user-role.ts`，无需新增底层权限判断逻辑。

## 四、数据字段展示规范
本章节仅列出存在特殊处理规则的字段；设计稿中出现的其余所有展示字段，均按设计稿标注的文案、格式、单位直接渲染，不做额外数据转换。

| 字段名称 | 展示处理规则 | 单位 |
| :--- | :--- | :--- |
| 上课时长 | 仅展示整数数值；若接口返回值包含小数，直接截断小数部分及后续内容，不做四舍五入处理 | 分钟 |
| 教案数量 | 按接口返回的数值正常展示 | 份 |

### 通用还原要求
设计稿内所有视觉元素、字段、标签、图标、分隔符、辅助文案等均需完整还原，不得因未在本表格中单独列出而省略或自行修改样式。

## 五、缺省状态规则
缺省规则适用于组件内全部展示字段，按单字段粒度独立生效，不采用整体缺省判断逻辑：
- 当单个字段数据为空、接口返回异常或字段获取失败时，仅该字段对应的展示区域切换为缺省样式；
- 各字段的缺省状态互相独立、互不影响，无需所有字段同时缺失才触发缺省展示；
- 所有字段的缺省视觉样式均以缺省状态设计稿为准。

## 六、头像组件实现规则
组件内的用户小头像采用纯CSS方案实现，无需使用真实头像图片：
1.  底色：通过CSS设置背景色作为头像底色；
2.  文字：取用户姓氏的第一个汉字作为头像展示文字；
3.  复姓兼容：复姓场景同样仅取姓氏的第一个汉字，不完整展示复姓。

## 七、组件分层架构（业务逻辑与视图分离）
为保证组件可复用性与可扩展性，采用「基础展示组件 + 业务容器组件」双层分离架构，严格拆分视图层与业务层职责，解除业务耦合。具体文件组织与目录划分遵循项目现有工程规范，不做强制路径要求。

### 1. 基础展示组件（纯视图、无业务、可复用）
- **定位**：无任何业务逻辑的纯渲染组件，仅通过 Props 接收标准化数据并输出UI，不依赖业务权限工具、接口请求与项目环境。
- **核心职责**：严格对齐Figma设计稿还原全部视觉元素与字段；根据入参自动切换对应字段的正常/缺省展示态；内置头像渲染能力；支持多尺寸下的响应式自适应展示。
- **复用性**：可在任意业务场景中直接引入使用，仅需传入符合格式要求的Props即可。
- **Props 入参定义**：

| 参数名 | 类型 | 说明 |
| :--- | :--- | :--- |
| courseDuration | `number \| null \| undefined` | 上课时长（已完成整数处理的分钟数），值为空时自动触发该字段缺省样式 |
| lessonPlanCount | `number \| null \| undefined` | 教案数量（单位：份），值为空时自动触发该字段缺省样式 |
| userName | `string` | 用户完整姓名，用于生成头像文字 |
| avatarBgColor | `string` | 可选，头像背景色；不传则使用组件内置默认色值 |
| 其余设计稿字段 | 对应数据类型 \| null \| undefined | 设计稿中其余所有展示字段，均通过Props透传，值为空时触发对应字段缺省样式 |

### 2. 业务容器组件（业务逻辑层）
- **定位**：对接当前业务系统的容器层，仅处理业务逻辑，不编写具体UI样式代码。
- **核心职责**：
  1.  调用项目现有角色权限工具，执行普通教师岗位权限判断，控制组件整体是否渲染；
  2.  发起后端接口请求，或读取本地Mock数据，获取原始业务数据；
  3.  执行数据格式化：按规则完成上课时长的整数截断、单位拼接等前置处理；其余字段按接口原值透传；
  4.  完成全字段单粒度缺省状态判断，将处理完成的标准化数据透传给基础展示组件。
- **依赖范围**：仅依赖业务侧的权限工具、接口请求方法，不耦合任何视图样式代码。

### 3. 通用头像子组件
将头像能力独立抽离为全局可复用的基础组件，内置“背景色+首字渲染、复姓取首字”逻辑，接收「姓氏文本、背景色」参数，可在项目其他场景直接复用。

## 八、UI组件与样式规范
1.  **组件复用原则**：UI实现优先复用 Element Plus 组件库原生组件，避免重复开发基础控件；可基于现有组件进行二次样式定制与功能封装，在严格对齐设计稿效果的前提下，最大化复用组件库能力。
2.  **样式隔离要求**：所有自定义样式必须做作用域隔离，仅对当前组件内部生效，不得污染全局样式、不得影响项目内其他页面与组件。样式隔离方案遵循项目现有工程规范，确保样式作用范围完全可控。
3.  **响应式适配规范**：
    - 组件需具备完整的响应式适配能力，兼容项目覆盖的主流屏幕尺寸与分辨率，在不同视口宽度下布局合理、内容完整展示，无溢出、错位、遮挡、文字截断等视觉异常。
    - 响应式断点与适配策略统一遵循项目现有前端响应式规范，不自定义全局断点；组件内部可根据容器宽度对间距、排列方式、字号做弹性调整，保证信息可读性与视觉协调性。
    - 适配过程中需严格保留设计稿核心视觉层级与元素关系，仅做布局弹性适配，不得擅自修改核心样式与字段展示逻辑。
    - 优先利用 Element Plus 自带的栅格系统、响应式API实现适配能力，减少冗余自定义样式。
4.  **可延展设计**：组件整体以工程化、组件化、可延展为设计目标，结构清晰、职责单一，预留合理的扩展插槽、配置项与钩子，支持后续字段新增、样式调整与功能迭代，无需重构核心结构。

## 九、Mock数据方案
开发阶段先行使用Mock数据完成联调，不依赖真实后端接口，待接口正式就绪后可无缝切换。

1.  **存放规范**：Mock数据的文件位置与组织方式遵循项目现有Mock管理规范，本需求不强制指定具体存放路径。需保证Mock数据与组件业务代码、视图逻辑分离，便于后续统一替换与维护。
2.  **全字段覆盖要求**：Mock数据需覆盖设计稿中所有展示字段，每个字段均需支持正常值与空值两种状态，可单独切换调试。
3.  **场景覆盖要求**：需预置以下典型场景，支持快速切换调试：
    - 全量正常数据场景：所有字段均返回合法数值，用于正常展示态调试；
    - 单字段缺省场景：分别覆盖上课时长、教案数量及其余字段单独为空的场景，用于验证单字段缺省逻辑；
    - 全字段缺省场景：所有数据字段均为空，用于全缺省场景验证。
4.  **边界验证数据**：
    - 上课时长需提供带小数的原始值（如 `128.75`），用于验证整数截断逻辑；
    - 用户姓名需同时提供单姓、复姓两类数据，用于验证头像取字逻辑。

## 十、开发要求
1.  视觉还原需严格对齐Figma设计稿的尺寸、色值、间距、字体与排版规范，全字段完整还原，保证1:1还原效果；
2.  所有数据处理逻辑需兼容接口异常、字段缺失、数值格式异常等边界场景；
3.  分层边界需清晰，禁止在展示组件中写入业务判断、接口调用等不可复用逻辑；
4.  优先复用 Element Plus 组件库能力，样式严格执行隔离规范，避免全局样式污染；
5.  必须完成多屏幕响应式适配验证，覆盖项目主流分辨率，确保不同视口下展示正常；
6.  组件设计需具备可扩展性，遵循工程化与组件化开发规范，便于后续迭代维护；
7.  已明确特殊处理规则的字段严格按规则执行，未明确规则的字段与样式一律以设计稿为准，不得自行修改；
8.  所有文件的目录划分、存放路径均遵循项目现有前端工程规范与团队约定，本需求不做强制指定。
