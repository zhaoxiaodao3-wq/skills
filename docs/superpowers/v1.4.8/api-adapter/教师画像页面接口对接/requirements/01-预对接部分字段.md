# 教师画像页面 — 预对接部分字段

> **背景**：后端已提供接口字段约定文档（`docs/TeacherProfileRspVO接口文档.md`，对应 `TeacherProfileRspVO`），但真实 HTTP 接口尚未就绪。本需求为**预对接**：在真实接口接入前，建立 API 响应 → 页面数据的转换链路。
>
> **接口文档**：[`TeacherProfileRspVO接口文档.md`](../docs/TeacherProfileRspVO接口文档.md)（2026-07-03）；[`PostClassReportVO变更说明.md`](../docs/PostClassReportVO变更说明.md)（2026-07-07，`dimensionScore` 结构变更）
>
> **涉及代码**：`src/pages/school/teacher-portrait/`（aggregate 类型、mock、各 Container）

### 核心原则：Mock / Slice 格式为最终数据契约

页面当前 mock 数据格式已按**原型需求（Figma）**约束定型，具体体现在：

- 类型定义：`types/aggregate.ts` 中各 `*Slice` 类型
- 示例数据：`mock/teacher-portrait-aggregate.mock.ts`
- 消费方式：各 Container 的 normalize / viewModel 逻辑

**接口返回的数据格式若与 mock/slice 不一致，一律由 Adapter 转换成与 mock 一致的结构后再注入 aggregate。** 不修改 Container、不修改组件展示逻辑、不因接口形态而调整页面数据契约。

**注意**：部分 UI 文案（如**课堂特征**、综合等级 pill）不在 slice 内，由 Container 从 slice 派生，**接口无对应字段** — 详见 **§三**。

数据流向：

```
TeacherProfileRspVO（后端原始响应）
        ↓  Adapter（本需求核心交付）
TeacherPortraitAggregate.*Slice（与 mock 同构）
        ↓  Container normalize（保持不变）
ViewModel → View 渲染
```

### 3.1 三层职责

### 3.3 课堂结构清晰度 — 汇总区字段明细

View 底部三块（`ClassroomStructureClarityView.vue`）：

| UI 文案 | ViewModel 字段 | 代码来源 | 接口字段 | 预对接策略 |
|---------|----------------|----------|----------|------------|

| 综合等级 | 分数区间（含） | 课堂特征 |
|----------|----------------|----------|
| 卓越 | 85～100 | 结构清晰，学生能清楚把握课堂脉络 |

派生逻辑（`ClassroomStructureClarityContainer.vue`）：

1. 读取 slice.`dimensions`，各维度 `score` 做整数截断；

**当前结论**：接口 `level` 只有等级名称、**没有**特征描述字段；**课堂特征不会也不能由 Adapter 从接口映射**，除非后端新增字段且改动 Container（超出本次预对接范围）。

## 四、数值精度与舍入约定

> mock/slice 存**原始数值**；**展示**时由 Container 按 `utils/number-format.ts` 截断。**Adapter 只做单位换算，不做小数位截断、不做四舍五入。**（数据分层见 **§三**）

### 4.1 分层职责

| 层级 | 职责 | 是否截断/四舍五入 |
|------|------|-------------------|
| **Adapter** | 结构/命名/单位换算（如 ratio ×100） | ❌ 不截断、不四舍五入，保留换算后的完整 `number` |
| **Slice（mock 同构）** | 存原始数值，供 Container 消费 | 与 mock 一致：可含多位小数（mock 注释「ratio 含多位小数用于截断验证」） |
| **Container** | 格式化为 ViewModel 展示文案 | ✅ 按字段类型调用截断函数（见 §4.2） |

公共工具（`src/pages/school/teacher-portrait/utils/number-format.ts`）：

```ts
/** 占比：保留 1 位小数，截断不四舍五入 */
truncateToOneDecimal(value)  // Math.trunc(value * 10) / 10 → toFixed(1)
/** 整数截断（上课时长、维度均分） */
truncateToInteger(value)     // Math.trunc(value)
```

**统一规则：全页面采用截断（trunc），不四舍五入（round）。**

### 4.3 Adapter 精度规则（实施要点）

1. **ratio 类字段**（我的教案、课堂教学内容评价、课堂语言行为）：Adapter 完成 `×100` 或 `count/total×100` 后**直接写入 slice**，不在 Adapter 内 `toFixed` / `Math.round` / `Math.trunc`。
2. **score 类字段**（维度均分）：课堂教学内容评价写 `dimensionScore.<key>` 裸分值；课堂结构清晰度写 `*.averageScore`；均**原样**写入 slice，精度截断交给 Container。
3. **count / maxScore / totalCount 类**：期望为整数，Adapter 直接映射；若接口返回小数，**不四舍五入**，可用 `Math.trunc` 取整后写入 slice（与 Container 整数展示一致）。
4. **单测验证**：接口 ratio=`0.08649` → slice.ratio=`8.649` → Container 展示 `8.6%`（非 `8.7%`），验证截断链路透传正确。

## 五、Adapter 转换明细清单

> **格式以 mock/slice 为准。** 下表逐字段列出：mock 目标长什么样、接口给的是什么、哪里不一致、Adapter 怎么转。
>
> 转换类型说明：
>
> | 类型 | 含义 |
> |------|------|
> | **直接映射** | 字段名/结构一致，原值写入 |
> | **字段重命名** | 语义相同，字段名不同 |
> | **结构重组** | 接口扁平/嵌套对象 → mock 数组或嵌套结构 |
> | **key/语义映射** | 枚举 key 或业务含义不同，需对照表转换 |
> | **单位换算** | 数值量纲不同（如 ratio 小数→百分比）；**换算后不截断、不四舍五入**（精度见 §四） |
