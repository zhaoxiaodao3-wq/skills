# 等级数量明细 · 原始需求

**版本：** V1.7.1 · **类型：** feature · **提出日期：** 2026-10-19
**页面：** 四个权限页公共（校长 `principal-cockpit-2` / 年级长 `grade-overview` / 学科组长 `subject-overview-2` / 备课组长 `plan-lessons`）

## 需求原文

四页公共组件「等级数量明细」。与「整体趋势与等级明细」在同一模块，但上半部分（整体趋势）由其他同事负责：

- 每个页面新建**一整个模块**，上半部分用**截图占位**，下半部分（等级数量明细）本次实现。
- 等级明细就是**表格组件**，按设计稿来，**带分页**。
- 每个权限页**筛选项不完全一致**：
  - 校区权限（校长）：周期、年级、科目（均接口返回）；**周期选项随上方组件「按月/按周」变化**
  - 备课组长：周期 + 班级
  - 学科组长：周期 + 年级
  - 年级长：周期 + 科目
- 按**通用业务组件**设计；有遗漏由 Agent 补充，不明白找用户确认。

**设计稿：** Figma node `9913:48657`（整模块）；占位用子节点渲染 `9913:48658`（模块头行）+ `9913:48691`（整体趋势区），已归档 `assets/ph-trend-module-header@2x.png` / `ph-trend-section@2x.png`。
**表头差异：** 用户提供四张原型截图（对话附件），按页可配置列。

## P1 确认记录（2026-10-16，用户逐条答复）

1. 表头首列：Figma 稿写「教师」为**稿误**，列内容为「第N周」（首列表头文案见待定点 #12）。
2. 按周/按月：**默认按周**；组件保留 `periodType` 入参（'week'|'month'），#13 筛选选项接口带该入参；同事组件接入后由页面传真实值。
3. 模块位置：四页**页尾追加**为最后一个模块。
4. 占位：两张渲染图上下拼（gap 20）；**四页暂共用**同一套占位图。
5. 表头**按页可配置**（四张截图）：
   - 校长(campus)：周期 / 日期范围 / 年级 / 科目 / 优秀 / 良好 / 合格 / 待改进 / 合计 / 优秀Δ / 良好Δ / 合格Δ / 待改进Δ（13 列）
   - 年级长(campus-grade)：无年级列（自身年级维度）（12 列）
   - 学科组长(campus-stage-subject)：无科目列（自身科目维度）（12 列）
   - 备课组长(campus-grade-subject)：第三列为**班级**（12 列）
6. `subject-overview-2` / `principal-cockpit-2` **同步模块卡片化**（同 grade/plan 结构）。
7. 分页默认 **10** 条/页；切任何筛选重置回第 1 页。
8. Δ 列：后端返回字符串原样（`'+1'/'-1'/'0'/'-'`），前端按规则着色不重算；「合计」后端出。
9. 行序：按周期升序，后端保证、前端不重排。
10. 空数据：el-table 内置空态「暂无数据」，不另做占位块。
