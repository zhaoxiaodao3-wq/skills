# 原始需求：概览路由与数据权限（1.7.1 第一个需求）

> 来源：用户口述（2026-10-15）
> 所属应用：`apps-development-platform/apps/data-board`（数据看板）
> 版本：V1.7.1

## 背景

1.7.1 版本共四个页面（四个菜单），本人只负责其中两个，菜单后续由后端返回，本需求先在前端写死本人负责的两个菜单。

## 需求内容

1. **路由与页面**
   - `/grade-overview` 年级长概览
   - `/plan-lessons` 备课组长概览
   - 页面内容先空白，本需求主要是把路由建出来
2. **数据权限控制**
   - 不同页面需要不同的数据权限才能看到正常内容；仅有路由权限但无对应数据权限（或更高级权限）时，进入页面只展示错误提示
   - 当前共四种数据权限：
     1. 校区
     2. 校区+年级
     3. 校区+学段+科目
     4. 校区+年级+科目
   - 权限等级（高级权限可看低级页面）：`校区` > `校区+年级` 或 `校区+学段+科目` > `校区+年级+科目`
   - 本需求两个页面对应的数据权限：
     - 年级长概览：`校区+年级`
     - 备课组长概览：`校区+年级+科目`
3. **封装要求**
   - 权限判断希望封装成 hooks（composable）或采用更合理的方案；后续很多接口请求都需要依赖权限判断
4. **Mock 要求（重要）**
   - 本版本接口基本没有，部分内容需要写死或 mock
   - **文档必须写清楚哪里是写死/mock、哪里后续需要接接口**，明确接口替换点

## P1 结论（2026-10-16 用户确认）

1. **principal-cockpit 占位路由：不删任何东西**，保留原样
2. **权限封装形态：hooks + 页面级守卫组件**（方案 A）
3. **偏序关系确认**：`校区+学段+科目` 与 `校区+年级` 互不覆盖，前者看不了年级长概览
4. **数据权限来源：先按「在用户信息里」设计**（后端计划将数据权限放入用户信息接口返回），本期 mock
5. **模块名「概览路由与数据权限」确认**
