# 二维码分享组件 · 补充需求

> 说明：在 [01-原始需求.md](./01-原始需求.md) 已交付基础上，强化「先请求再展示」与二维码加载态。

## 一、补充点

1. **点击按钮后先请求接口拿到链接**，再展示到弹窗；加载中链接区/二维码区应有 loading，不提前用可编辑输入框填入假链接。
2. **链接只读不可编辑**（纯展示文本，非 input）。
3. **二维码区域**需具备：
   - 加载中：loading 动画（链接请求中或二维码生成中）
   - 加载失败：失败态文案
   - **重新生成**：失败或需要刷新时可点击重新请求链接并重新生成二维码

## 二、交互流程（修订）

1. 用户点击分享按钮 → 打开弹窗  
2. 弹窗内进入 loading：请求 `resolveShareUrl`（开发阶段可用 Mock Promise 模拟接口）  
3. 成功：展示只读链接 + 生成二维码  
4. 失败：链接区/二维码区展示失败态 +「重新生成」按钮  
5. 点击「重新生成」：重复步骤 2～4  

## 三、约束

- 仍为全局组件 `AppShareLink`；调用方传入 `resolveShareUrl`  
- 无 `resolveShareUrl` 时：可用 Mock URL，但二维码区域仍应有短暂 loading → 成功/失败路径，避免无反馈  
- 链接始终只读
