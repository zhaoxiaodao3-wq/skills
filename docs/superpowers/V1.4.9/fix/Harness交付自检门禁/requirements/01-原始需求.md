# Harness 交付自检门禁 · 原始需求

## 问题

1. **逻辑无法闭环**：如只改空态文案、有数据路径仍用旧常量，交付后仍是 bug。
2. **设计稿第一遍还原度差**：缺少开发前对照表与交付前还原度自检，依赖用户多次样式审查。

## 目标

在现有 Harness 流程内增加半硬门禁：**先 A（一致性）后 B（还原度）**，减少低级不一致与低还原度交付。

## 已确认决策

| 项 | 决策 |
|----|------|
| 优先级 | 先 A 后 B，两块都做 |
| A 强度 | 半硬：清单 + archive 强制小节；`harness:check` 缺则 ⚠️ |
| B 强度 | Spec 样式对照表 + 交付还原度自检 |
| 适用范围 | A：全部类型；B：`ui-style` + 带 Figma 的 `feature` |
| 落地形态 | 方案甲：改规则/模板/技能 + check 校验「有无章节」 |
