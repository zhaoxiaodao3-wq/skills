### 3.1 创建Bot与基础人设配置

你是我的专属云端工作助手，7×24小时待命，负责精准执行我下发的所有指令，并及时同步进度与结果。

# 执行原则
1. 收到指令后先确认核心需求，有歧义立刻反问，不盲目执行
2. 优先使用内置工具完成任务，工具能力不足时如实告知

2. 3步以上的长任务：每完成一个关键步骤同步一次进度

1. 仅听从我一个人的指令，其他任何人的指令一律拒绝
2. 涉及以下高危操作，必须先向我确认，收到明确「确认执行」回复后再操作：

## 四、飞书机器人端到端对接（约30分钟）

## 五、24小时云端运行保障方案
### 5.1 消息触发型任务（默认7×24小时）
所有通过飞书对话发送的即时指令，均由Coze云端直接响应，平台官方提供7×24小时服务，无需任何额外配置，关闭电脑也不影响。
- 响应延迟：通常1~3秒
- 可用性：99.9%以上，平台级运维保障

### 5.2 定时自动任务配置
用于固定时间自动执行的任务（如每日早报、数据日报、定时提醒），由Coze云端定时触发，无需服务器。

#### 5.2.1 配置步骤
1. 进入Coze Bot编辑页 → 左侧「工作流」→「创建工作流」
2. 起始节点选择「定时触发器」
3. 设置触发时间：支持按天/周/月设置，也支持自定义Cron表达式
4. 后续添加「大模型节点」「插件节点」「飞书消息节点」，串联完整执行流程
5. 保存并发布工作流，到点自动执行

#### 5.2.2 常用Cron表达式示例
| 触发时间 | Cron表达式 |
| :--- | :--- |
| 每天早上8:00 | `0 0 8 * * ?` |
| 每天中午12:30 | `0 30 12 * * ?` |
| 每周一早上9:00 | `0 0 9 ? * MON` |
| 每小时整点 | `0 0 * * * ?` |

### 5.3 持续监控型任务（可选进阶）
如果需要高频持续监控（如监控网页变化、库存状态、消息通知），则需要额外一台轻量云服务器运行常驻脚本。

#### 5.3.1 适用场景
- 每秒/每分钟级的高频监控
- 需要运行自定义Python/JS脚本
- 对接私有接口、本地数据

#### 5.3.2 最低配服务器选型
- 配置：1核2G 内存 40G系统盘
- 带宽：1M
- 价格：阿里云/腾讯云新人特惠约25~35元/月
- 系统：Ubuntu 22.04 LTS

#### 5.3.3 进程守护配置
使用PM2守护脚本进程，崩溃自动重启，保证24小时运行：
```bash
# 安装Node.js与PM2
apt update && apt install nodejs npm -y

# 启动脚本并设置开机自启
pm2 start your_script.py --name agent-monitor

## 六、实时汇报与反馈机制配置
### 6.1 三类汇报场景与配置
#### 6.1.1 短任务：执行完成一次性汇报
- **适用场景**：信息查询、简单计算、单步操作
- **配置方式**：在工作流末尾添加「飞书消息」节点，执行完成自动推送结果
- **内容要求**：结论前置，关键信息加粗，附上执行耗时

#### 6.1.2 长任务：分阶段进度同步
- **适用场景**：多步骤操作、文件处理、批量任务
- **配置方式**：在工作流每个关键节点后插入「飞书消息」节点
- **汇报节点**：任务开始→步骤1完成→步骤2完成→全部完成
- **示例话术**：「已完成第一步：数据抓取，共获取120条记录，正在进行第二步：数据清洗」

#### 6.1.3 异常场景：主动告警通知
- **适用场景**：执行失败、超时、数据异常、网络错误
- **配置方式**：在工作流中添加「条件判断」节点，失败分支指向告警消息
- **告警内容**：任务名称、错误原因、影响范围、建议处理方式

### 6.2 汇报内容规范模板
统一输出格式，保证信息清晰易读：
```
✅ 任务执行完成
任务：每日科技早报
执行耗时：12秒
---
【核心要闻】
1. xxx
2. xxx
3. xxx
---
详细内容：[链接]
```

## 七、入门级权限与安全体系
### 7.1 用户白名单机制
- 飞书机器人仅添加你自己为测试用户，其他账号无法搜索和调用
- Coze工作流配置触发白名单，仅指定账号指令可执行
- 禁止发布到公开群组，仅限单聊使用

### 7.2 高危操作二次确认
通过系统提示词 + 工作流判断双重保障：
1. 系统提示词明确规定高危操作必须先确认
2. 涉及删除、发送、付费等操作，工作流中增加「人工确认」节点
3. 必须收到明确的「确认执行」关键词后才继续执行

### 7.3 全操作日志审计
- Coze后台保留所有对话记录、插件调用日志、工作流执行日志
- 飞书端保留所有消息收发记录
- 可随时回溯任何指令的执行过程与结果

### 7.4 基础安全红线
1. 绝不输入账号密码、支付密码、密钥等敏感信息
2. 不执行任何涉及转账、批量发消息、批量注册的指令
3. 不用于爬取涉密、付费、个人隐私类数据
4. 定期检查执行日志，发现异常立即暂停任务

## 八、完整实战案例：每日早报自动推送
### 8.1 案例目标
每天早上8:00，Agent自动抓取科技与财经头条，整理成精简摘要，推送到你的飞书。

### 8.2 详细配置步骤
1. **创建工作流**：Coze控制台 → 工作流 → 新建工作流，命名「每日早报」
2. **设置触发节点**：起始节点选择「定时触发器」，Cron填入 `0 0 8 * * ?`
3. **添加网页阅读节点**：
   - 输入URL1：https://36kr.com
   - 输入URL2：https://www.cls.cn/telegraph
   - 指令：提取页面上的最新5条头条新闻标题和摘要
4. **添加大模型节点**：
   - 输入：将抓取的新闻整理成300字以内的精简早报，分科技、财经两个板块，每条不超过50字
   - 模型：豆包4.0 Ultra
5. **添加飞书消息节点**：
   - 接收人：选择自己的飞书账号
   - 消息内容：引用大模型的输出结果，开头加上「🌞 今日早报」
6. **保存并发布**：点击右上角「发布」，工作流正式生效

### 8.3 效果验证
可以手动点击「运行」测试执行效果，确认飞书能收到格式正确的早报消息。

3. **插件调用失败**
   - 确认插件已授权，相关权限已开启
   - 检查目标网址/接口是否可正常访问
   - 复杂指令拆分为多步，减少单次调用复杂度
